# 官网版本提醒接口

本目录是待部署的静态接口，不代表网站已上线。`latest.json` 与应用安装包分别部署；上传 EXE 本身不会自动改变版本信息。

1. 发布正式版并人工验证安装包后，将 `latest.json` 的 `version` 改为该版本（例如 `1.2.0`），`schemaVersion` 保持数字 `1`。
2. 将 JSON 放到官网 HTTPS 静态地址，返回 HTTP 200、`Content-Type: application/json`；建议 `Cache-Control: no-cache` 或短缓存。不要登录、重定向或返回 HTML。CORS 不影响原生 Qt 客户端。
3. 确定实际地址后，构建客户端时设置 `-DAGPLAYER_UPDATE_MANIFEST_URL=https://www.agplayer.com/实际路径/latest.json`。当前默认空地址，不发请求，并显示“更新服务尚未配置”。这个模板地址不能当作已经可用的接口。
4. 一旦客户端内的地址固定，后续每次发布只需上传安装包、更新官网下载页面和该 JSON，无需为每次版本发布改客户端检查逻辑。首次配置或将来更换接口地址则需要重新构建客户端。

客户端仅接受三段非负稳定版本号，按数字比较（1.10.0 大于 1.9.0）。预发布版本不通过此稳定通道推送。不读取音频或上传设备信息；10 秒总超时、64 KiB 响应上限、拒绝重定向、不使用 Cookie。错误不显示为“最新版”。发现更新后始终前往 `https://www.agplayer.com`，不会执行 JSON 中的下载链接，也不会自动下载/安装。

部署后验收：旧版→新版、相同版、较旧版、404/HTML、超时/离线。检查网页下载链接与 JSON 版本一致。尚未部署期间仅能完成本地协议/客户端测试，不能声称在线更新已可用。
