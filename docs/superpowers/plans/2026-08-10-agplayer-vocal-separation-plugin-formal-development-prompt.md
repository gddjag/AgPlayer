# AgPlayer 人声/伴奏分离插件——Codex 正式开发提示词 V2

> 使用方法：将本文从“正式任务”开始完整交给 Codex。产品方向与 UI 已确认，不再重新设计，不模仿 Trama 或 UVR5 的界面。Codex 必须先核实现有工程、形成实施计划，再按测试驱动方式分阶段实现。本任务只允许交付真实可运行功能，禁止占位、假进度和虚构兼容性。

## 正式任务

在 AgPlayer 中实现生产级“人声/伴奏分离”功能。

开始前必须完整阅读：

- `AGENTS.md`
- `docs/research/2026-08-09-agplayer-vocal-separation-feasibility.md`
- 仓库中的架构设计、构建说明、测试规范和现有音频工具实现

当前需求文档仓库可能不等于实际代码 checkout。先确认真实活动仓库、分支、未提交修改、Qt/CMake 构建入口和现有四个音频工具的实现位置。保留用户修改，不覆盖、不回退、不顺手重构无关模块。代码发现优先使用 codebase-memory-mcp；图索引不足时再使用 `rg`。

## 一、最终产品目标

- 技术栈：Qt 6、QML、C++17。
- 首发平台：Windows 10、Windows 11 x64。
- 后续平台：macOS、Linux、Android、iOS、HarmonyOS。
- 核心定位：极致轻量、原生性能、一套核心业务代码跨端复用。
- “人声/伴奏分离”集成在现有“音频工具”窗口中，使工具数量从 4 个变为 5 个。
- UI 属于 AgPlayer 自有设计，不复刻 Trama 或 UVR5 的布局、控件和品牌表达。
- 主播放器不携带 AI 模型、PyTorch、CUDA、ONNX Runtime 等大型依赖。
- 分离能力采用可选插件：用户第一次使用时下载，下载完成立即可用，不要求用户安装 Python、PyTorch、CUDA Toolkit、Visual C++ 运行环境或配置环境变量。
- 插件与模型完全分离；模型逐个按需下载，禁止一键下载全套模型。
- 分离运行在独立 Worker 进程；Worker、推理引擎或显卡驱动异常不得导致播放器退出。
- 后续升级分离引擎优先只更新插件；新增同架构模型优先只更新签名 Catalog 和模型文件。
- 生产构建零错误、零警告；没有真实 UI、真实音频和真实硬件证据前不得生成发布版 EXE。

## 二、最终架构：原生 UI + 自包含插件 + 外置模型

### 2.1 主程序

AgPlayer 主程序只包含：

- 音频工具入口与 QML 页面。
- 插件、模型、设备和任务状态协调。
- 受控下载、签名验证、哈希校验、原子安装与回滚。
- Worker 生命周期与 IPC。
- 波形显示、预览播放、缓存注册和结果导出。

主程序不得直接链接 PyTorch、CUDA 或模型推理代码；未安装插件时不得加载任何 AI 动态库。

### 2.2 自包含分离插件

插件下载包必须包含运行所需的 Worker、Engine、推理运行库、DSP 依赖和许可证文件。安装过程只能是：下载、校验、解压、原子启用；不得弹出第三方安装器，不得要求管理员权限，不得修改系统 PATH。

建议包类型：

```text
ag-separation-host-<platform>-<arch>
ag-separation-native-ort-<platform>-<arch>
ag-separation-compat-demucs-cpu-<platform>-<arch>
ag-separation-compat-demucs-gpu-<platform>-<arch>
```

工程体积目标仅用于预算，UI 必须显示发布 manifest 中的真实字节数：

- 原生 C++ + ORT CPU/DirectML 插件：目标下载体积 80–150 MB，不含模型。
- Demucs/PyTorch CPU 兼容插件：预计 300–700 MB，不含模型。
- CUDA 完整兼容插件：预计 1.5–3 GB，不含模型，只能作为用户主动下载的高级组件。

不要为了满足体积目标删除模型必需算子或伪造“完整兼容”。最终验收以裁剪、LTO、符号剥离后的 Release 实测结果为准。

### 2.3 引擎策略

- `htdemucs_ft` 默认作为“标准音质（Trama 同款）”。在 Native ORT 转换版完成数值、边界、整曲听感和性能等价验证前，使用稳定的自包含 Demucs Compatibility Engine。
- MDX 与 VR 只展示 Catalog 中已经验证的平台、Engine 和模型版本。
- Native ORT 负责经过转换验证的 ONNX 模型，优先用于轻量 CPU 和 Windows DirectML。
- 原始 `.pth/.th/.ckpt` 只能由受控 Compatibility Engine 加载；不可信来源不得执行。
- 新增模型只有在现有 Engine Adapter、profile schema 和算子集合均支持时，才能做到不升级主程序与 Worker。

### 2.4 跨平台核心边界

- 分离领域核心使用纯 C++17，只暴露版本化标准 C ABI。
- 核心不得依赖 QObject、QString、QProcess、QNetworkAccessManager 或平台路径规则。
- Qt 桌面端通过 Adapter 调用 C ABI；HarmonyOS 未来通过独立 Node-API/NAPI Adapter 接入 ArkUI。
- 各平台 Worker、Engine Pack 和硬件后端允许分别构建，但共享协议、Catalog schema、错误码、缓存键和结果验证规则。

## 三、音频工具入口与首次使用

- 在现有四个音频工具上增加第五个：`人声/伴奏分离`。
- 采用现有音频工具同一窗口、第五页方式；不新增另一套重复窗口。
- 页面路由使用稳定工具 ID，禁止依赖容易变化的裸数组下标。
- 原有四个工具的顺序、行为、Controller、持久化状态和快捷键不得回归。

用户第一次点击入口时：

1. 主程序执行真实 `probe`，检查 Host、所选模型所需 Engine、协议版本和安装目录。
2. 插件缺失时弹出“下载人声分离插件”对话框。
3. 对话框展示插件名称、版本、发布者、下载体积、安装后占用、支持的 CPU/GPU、许可证、保存目录和官方说明链接。
4. 文案明确：`插件已包含运行环境，下载完成即可使用，无需另外安装 Python、CUDA 或其他组件。`
5. 用户确认后执行断点下载、签名验证、SHA-256 校验、安全解压、原子安装和 Worker 握手。
6. 只有 `hello/probe` 成功后才能显示“插件可用”；文件存在但握手失败必须显示真实错误。
7. 进入页面后提示：`模型需要按需下载，只下载你需要的即可。`
8. 默认选中 `htdemucs_ft`；模型未下载时不能开始分离，但对应下载按钮必须可用。

## 四、已确认 UI 规格

最终页面从上到下分为：工具导航、歌曲信息、模型选择与管理、模型目录与计算设备、三轨波形预览、底部任务操作。普通模式和专业模式同时展示，不使用折叠区，不使用“更多专业模型”。

### 4.1 顶部工具导航

保留现有四项并新增第五项：

```text
轻度剪辑 | 格式转换 | 元数据修改 | 文件名处理 | 人声/伴奏分离
```

当前项使用 AgPlayer 蓝色高亮和底部指示线。不得改变原有四项图标和语义。

### 4.2 歌曲信息栏

显示：

- 封面。
- 文件名。
- 总时长。
- 文件格式。
- 采样率。
- BPM。
- `更换歌曲`按钮。
- 任务状态：`等待开始 / 正在分离 / 分离完成 / 分离失败 / 已取消`。

BPM 必须来自真实分析结果；尚未分析成功时显示 `BPM —`，禁止写演示数字。

### 4.3 模型卡片区

桌面宽屏默认同屏展示三张主要卡片：

1. 普通模式：`标准音质`，模型 `htdemucs_ft`，带`推荐`标记。
2. 专业模式：`KTV 纯净伴奏`，展示已验证 MDX 模型。
3. 专业模式：`极速轻量`，展示已验证 VR 模型。

默认场景文案：

```text
标准音质（Trama 同款）：适合日常歌曲，乐器保留完整
KTV 纯净伴奏（MDX）：强力消除人声，适合翻唱 K 歌
极速轻量（VR）：低配电脑快速处理，优先生成纯净伴奏
```

每张模型卡片必须由 Catalog 数据驱动并显示：

- 产品显示名称。
- 精确模型名称。
- 模型家族：Demucs、MDX 或 VR。
- 提供商/作者。
- 一句话介绍与适用场景。
- 官方仓库名称和可点击链接。
- 下载文件大小与安装后占用。
- CPU/GPU 支持。
- 模型状态。

模型状态至少包括：

```text
未下载 | 下载中 | 已暂停 | 校验中 | 安装中 | 已下载 | 更新可用 | 已损坏 | 不兼容 | 实验性
```

交互规则：

- 已下载模型可以选中并立即用于任务，显示清晰选中描边和勾选图标。
- 未下载模型可以成为“待下载选择”，因此默认 `htdemucs_ft` 即使未下载也保持选中描边；但它不能进入可执行状态，`开始分离`必须禁用，`一键下载`保持可点击。
- 下载中显示真实百分比、已下载/总字节数、速度、剩余时间及`暂停/继续/取消`。
- 点击官方仓库链接调用系统浏览器打开 Catalog 验证过的一手来源。
- 不允许把社区镜像标记为官方；没有可验证官方仓库时不显示“一键访问官方仓库”的虚假入口。
- 后续新增同 profile 模型由 Catalog 自动进入对应类别；不得把未来模型列表硬编码在 QML。
- 模型多于宽屏容量时使用同区域横向滚动或分页，不把普通/专业模式重新隐藏到折叠面板。

### 4.4 模型保存目录与处理设备

模型卡片下方显示：

```text
模型保存目录  <实际路径>  [打开目录] [更改]
选择处理设备： [CPU 图标 CPU] [GPU 图标 GPU]
```

设备选择禁止使用下拉框。CPU、GPU 两个按钮必须直接显示，带图标、文字、选中状态和可访问名称。

- CPU 提示：`兼容稳定，适合所有支持的电脑。`
- GPU 提示：`速度更快，需要已验证的显卡和加速组件。`
- 默认策略：GPU 已通过当前模型完整探测时推荐 GPU，否则选中 CPU。
- 不显示或不启用未经真实探测的 GPU。
- GPU 可用但加速组件未安装时，按钮显示下载提示；不得后台自动下载。
- 用户明确选择 GPU 后初始化失败，不得静默切换；提供`改用 CPU`操作。
- 自动恢复历史选择前必须重新探测当前模型、插件和设备兼容性。

### 4.5 三轨波形预览

分离区域固定显示三条共享时间轴的波形：

1. `原曲`：中性灰色。
2. `人声`：AgPlayer 蓝色。
3. `伴奏`：绿色。

每条轨道左侧显示：

- 轨道名称。
- 播放/暂停按钮。
- 可点击的喇叭图标，用于静音/恢复当前轨道。
- 横向音量滑块。

波形规则：

- 三轨使用同一起点、总时长、缩放比例和共享播放位置。
- 鼠标点击任意波形位置，立即把共享播放位置跳转到该时间，并从当前试听轨道继续预览。
- 拖动播放线支持连续定位；定位期间不得阻塞 UI。
- 当前播放线贯穿三条轨道。
- 播放线上方显示浮动时间胶囊，例如 `02:08`。
- 波形区域底部只显示一条共享时间刻度，从 `00:00` 到歌曲总时长。
- 轨道右侧不再重复显示每轨时间。
- 波形尽可能占满轨道横向空间，不为重复文字预留空白。
- 点击另一轨道播放时保持共享时间位置，切换采用短交叉淡化，不从头播放。
- 每条轨道可以单独试听；同一时刻只允许一个轨道播放按钮处于播放态。
- 删除每条轨道的`独奏`文字和独立开关，不保留第二套静音控制。
- 点击喇叭图标直接切换当前轨道的`有声/静音`状态，图标必须同步显示音量波纹或静音斜线；再次点击恢复静音前的音量。
- 喇叭静音与音量滑块绑定：拖动已静音轨道的音量滑块到大于 0 时自动恢复有声；滑块归零时显示静音图标。
- 分离前仅原曲波形可播放；人声、伴奏轨显示明确的未生成状态，不绘制假波形。

删除旧设计中的整条`当前预览 / 时间 / 全部停止`大播放组件。页面不得再添加第二套总进度条，因为共享播放线、时间胶囊和底部时间刻度已经承担该功能。

### 4.6 底部任务操作

底部操作区包含：

- `重新分离`
- `导出人声`
- `导出伴奏`
- 主按钮：`开始分离 / 取消分离 / 分离完成`

状态规则：

- 输入、插件或模型不完整时，`开始分离`禁用并显示准确原因。
- 分离中主按钮变为`取消分离`，显示真实阶段与进度。
- 分离完成后导出按钮启用；主按钮显示`分离完成`且不可重复触发。
- `重新分离`仅在已有结果时启用，使用当前歌曲、模型、设备和参数重新创建任务。
- 导出使用文件选择器和真实写入结果；失败不得显示成功。

## 七、目录规范

```text
<UserData>/AgPlayer/separation/
  host/<version>/
  engines/<engine-id>/<version>/
  accelerators/<accelerator-id>/<version>/
  models/<model-id>/<version>/
  models/inbox/
  cache/<source-hash>/<profile-hash>/
  downloads/<package-id>/<version>/*.partial
  staging/<job-id>/
  logs/
  active.json
```

- Windows 默认 `<UserData>` 为 `%LOCALAPPDATA%`。
- 便携版允许 `<AgPlayer>/data/separation`，但必须先验证可写和剩余空间。
- 模型目录可以由用户更改；打开目录和更改目录都必须真实可用。
- 移动模型目录采用校验后的迁移或重新下载，不能只保存一个失效路径。
- 路径基于当前应用位置和配置解析，禁止开发机绝对路径。

## 八、Worker 与协议

桌面端使用 `QProcess` 启动 `ag-separation-worker`。首版每个任务使用独立进程；Windows 使用 Job Object 保证播放器退出后回收 Worker。

协议使用版本化 NDJSON 或长度前缀 JSON。首版命令：

```text
hello
probe
start
cancel
shutdown
```

事件：

```text
accepted
progress
log
completed
failed
cancelled
```

所有消息包含 `protocol_major`、`protocol_minor`、`request_id`。协议只传稳定错误码和结构化参数，不传依赖中文文本判断的业务状态。同一 major 内忽略未知字段并保持向后兼容。

Worker 默认禁网；所有下载由主程序受控下载模块完成。Worker 只获得源文件只读权限、模型目录只读权限和当前 staging 目录写权限。

## 九、任务、缓存与播放闭环

- 默认同时只执行一个分离任务。
- 下载、解压、模型加载、推理和导出不得运行在 UI 线程或音频回调线程。
- Worker 按 segment 处理，不把整曲 PCM 常驻内存。
- 输出先写 staging；验证可解码、stem 数量、采样率、声道、时长和非空后原子提交。
- 缓存键至少包含源音频 SHA-256、模型 SHA-256、Engine 版本和全部影响结果的参数。
- 默认缓存格式为无损 FLAC；验证基准允许保留 32-bit float WAV。
- 删除模型不得删除已有分离结果；模型管理与缓存清理是两个独立动作。
- 原曲、人声、伴奏必须共享播放时间轴；切换试听不重置位置。

## 十、错误与恢复

必须提供稳定错误码并覆盖：

- 插件未安装、协议不兼容、签名失败、哈希错误、磁盘不足、无权限。
- 网络中断、暂停、继续、取消、断点文件损坏。
- 模型缺失、模型损坏、Engine 不支持 profile、模型许可证无效。
- CPU 初始化失败、GPU 不支持、GPU 加速组件缺失、显存不足、驱动错误。
- Worker 崩溃、超时、用户取消、输出验证失败、导出失败。

Worker 异常退出后 AgPlayer 必须继续正常播放，并允许用户重试或切换 CPU。日志不得记录用户完整媒体路径、认证令牌、私钥或敏感配置。

## 十一、实施阶段

Codex 必须根据真实代码仓库写出按文件、测试和小提交拆分的实施计划，再执行以下阶段：

### 阶段 1：现状审计与契约

- 定位第五工具入口、QML 页面框架、音频预览、波形、下载器、设置存储和测试入口。
- 定义纯 C++17 领域类型、稳定错误码、C ABI、Worker IPC、Catalog 和插件 manifest schema。
- 创建仅供自动化测试使用的 Fake Worker/Fake Engine；不得出现在生产 UI。

### 阶段 2：自包含插件安装闭环

- 实现插件 probe、真实大小展示、断点下载、签名/哈希验证、安全解压、原子安装、握手、更新和回滚。
- 验证干净 Windows 10/11 系统无需安装 Python、PyTorch、CUDA Toolkit 或额外运行环境即可启动 CPU 插件。
- GPU 组件必须单独探测和按需下载。

### 阶段 3：Catalog 与模型管理

- 实现官方来源验证、固定 revision、多 artifact 下载、进度、暂停、继续、取消、删除、重校验和目录迁移。
- 证明只更新 Catalog 和同 profile 模型文件即可在 UI 出现新模型；未知 profile 必须拒绝。

### 阶段 4：最终 QML UI

- 音频工具从 4 项变为 5 项。
- 完成歌曲信息、BPM、三张模型卡、模型目录、CPU/GPU 直选、三轨波形、共享时间轴和底部任务操作。
- 删除旧的高级折叠区、设备下拉框、轨道右侧时间和整条“当前预览/时间/全部停止”组件。
- 完成键盘导航、焦点、屏幕阅读器名称、125%–200% 缩放和最小窗口尺寸测试。

### 阶段 5：稳定分离引擎

- 接入 `htdemucs_ft` CPU Compatibility Engine，完成真实歌曲分离。
- 接入已验证 MDX、VR 模型。
- GPU 只在目标设备完成整曲验证后进入正式 Catalog。

### 阶段 6：波形与试听闭环

- 生成真实原曲、人声、伴奏波形缓存。
- 验证波形点击定位、拖动、轨道切换、音量、喇叭静音/恢复、共享播放线、时间胶囊和交叉淡化。
- 验证导出人声、导出伴奏、重新分离和删除模型后结果仍可播放。

### 阶段 7：Native ORT 与跨平台

- 对候选模型做转换、数值、整曲听感、性能和边界等价测试。
- Windows 验收后再增加 macOS/Linux Engine Pack。
- Android/iOS 复用 C ABI并使用平台生命周期 Adapter。
- HarmonyOS 必须先完成 arm64 真机推理、N-API、内存、温升和后台限制 POC，才能宣称支持。

## 十二、强制验收矩阵

至少证明：

- 现有四个工具无回归，第五工具真实进入分离页面。
- 插件缺失时显示准确安装弹窗；取消可恢复；下载后无需安装环境即可握手。
- 插件、模型和 GPU 组件分别按需下载，不发生隐式全量下载。
- 普通与专业模型同屏展示，字段、官方链接、大小、状态和进度来自真实 Catalog。
- CPU/GPU 采用带图标的直接选择按钮，不存在设备下拉框。
- 默认 `htdemucs_ft`，未下载时不能开始，下载完整逻辑模型包后才能启用。
- 三轨真实波形、共享播放线、底部时间轴、浮动时间胶囊和点击定位全部工作。
- 没有旧“当前预览/时间/全部停止”大播放条，没有每轨重复时间。
- 人声和伴奏能够独立播放、调节音量，并通过喇叭图标静音/恢复；轨道切换不跳回起点。
- CPU 完整任务成功；GPU 成功与失败路径均有真机证据。
- Worker 崩溃、显存不足或模型损坏不会导致播放器退出。
- 下载中断、续传、取消、错误签名、错误哈希、路径攻击、磁盘不足和无权限均通过测试。
- 缓存随源音频、模型、Engine 和参数变化；错误缓存不被复用。
- 真实歌曲结果可播放、时长对齐、可导出。
- Windows 10/11 Release 构建零错误零警告。
- 报告主程序基础包、插件压缩包、插件安装后、单模型下载和缓存的真实体积。

完成标准不是“编译通过”或“CLI 生成文件”。必须同时提供自动化测试输出、真实 UI 截图、真实分离日志、CPU/GPU 设备证据、播放器内试听与导出证据。

## 十三、明确禁止

- 禁止把 AI 运行时或模型打进主播放器。
- 禁止要求用户安装 Python、PyTorch、CUDA Toolkit或手工配置依赖。
- 禁止在主进程执行模型推理。
- 禁止用 QML 直接下载、解压、启动进程或解析安全 manifest。
- 禁止把普通模式和专业模式重新做成折叠面板。
- 禁止使用 CPU/GPU 下拉框。
- 禁止在轨道控制区显示`独奏`文字或独奏开关；静音/恢复只由喇叭图标控制。
- 禁止恢复底部大播放组件或轨道右侧重复时间。
- 禁止虚假模型、假波形、假 BPM、假进度、假 GPU、假成功和无行为占位控件。
- 禁止硬编码未来模型清单或跟随 Hugging Face `main`。
- 禁止把第三方镜像标记为官方仓库。
- 禁止把 Trama 当作模型家族；正确表达是 `htdemucs_ft（Trama 同款）`。
- 禁止把能识别文件扩展名等同于支持全部 UVR5 模型。
- 禁止固定开发机绝对路径。
- 禁止未经许可证确认就分发模型或重打包上游权重。
- 禁止未完成真实 UI、音频、崩溃隔离和硬件验收就打包 EXE。
