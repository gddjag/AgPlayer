# AgPlayer 标签管理、统一歌曲列表与轻量波形缩略图设计

## 1. 目标与完成门禁

本设计承接 `AgPlayer 歌曲列表波形缩略图开发提示词｜极致轻量版_歌单标签整合版.md`，视觉真值为 `标签管理.png`（1447×1087）。目标是在不改变播放核心、主播放器波形算法、FFmpeg 播放链路和现有跨平台技术栈的前提下，完成：

- 下方工作区统一为左侧媒体库/歌单/资源文件夹、中间共享歌曲列表、右侧标签管理栏。
- 标签搜索、添加、筛选、重命名、删除、修改颜色与增量计数。
- 列表歌曲真实静态波形缩略图、36 色稳定映射、彩色/纯色设置与关闭近零负担。
- 资源文件夹添加、移除引用、懒加载层级展示和系统文件夹拖入。
- 歌曲单选/多选拖动的一次性半透明预览。
- 参考图同尺寸运行截图对比、功能、性能、播放隔离和高 DPI 验收证据。

完成定义不是“能够编译”。所有必须项必须在 `docs/development/` 中映射到代码、自动测试或真实运行证据；未执行的跨平台、真实硬件或规模测试必须明确标为待验收，不能报告为完成。

## 2. 已有基础与约束

现有数据链为 `LibraryModel → LibraryFilterModel → TrackList`。歌曲标签已保存在 `TrackRecord::tags`，通过 `TagsRole` 暴露并随 `library.json` 原子保存；歌单只保存 Track ID；`TrackList.qml` 已包含选择、收藏、评分、排序、右键菜单和内部拖放。标签管理必须复用这条链，不建立第二套歌曲模型或表格。

`WaveformProvider` 服务当前播放曲目，缓存未命中时会分析音频；不能让列表 delegate 逐行调用它。已有 `.agwf` v2 缓存包含真实 mix/bass/mid/high Peak，可作为缩略图唯一数据来源。列表缩略图只能 cache-only 读取，缓存未命中显示空白或细线，不得触发解码或分析。

`LibraryManagerController` 已具备监控文件夹、后台扫描、取消和导入能力，但当前 UI 未完整呈现目录树和移除操作，持久化路径也必须在应用启动装配中补齐。系统拖入继续复用 `NativeDropRouter`、Qt Drag & Drop 和 `ImportController`。

禁止新增第三方依赖、单独数据库、波形图片缓存、实时 FFT、Shader 动画、QML Canvas、`QQuickPaintedItem`、每个 Peak 一个 QML Item、无界缓存和新增长期后台线程。

## 3. 窗口与界面架构

保留现有主播放器窗口与可吸附 `ListWindow` 的窗口控制能力。参考图本身由上方播放器和下方圆角工作区组成；文档禁止的是下方左/中/右被拆成三个卡片或窗口。因此方案 A 不重写 `WindowController`，而是在同一个 `ListWindow` 内容面内建立连续三栏：

```text
SideNavigation | TrackList + SearchFilter | TagManagementPanel
```

三栏共用一个背景和外描边，只以 1 logical px 分隔线区分；左、中央、右各自独立滚动，任何一栏滚动不得重建另外两栏。现有列表窗分离/吸附能力继续保留，默认吸附状态按参考图呈现。

参考视口为 1447×1087。设计基准：下方工作区约 1420×684；左栏 256；右栏 328；中央自适应且最低约 680；表头 56–58；波形开启时歌曲行 62，关闭时恢复现有 42；底部筛选条 66–68；封面 34×34；缩略波形高 8–10、最高 12；标签胶囊高 28、圆角 14、三列、列间距 8–10。

歌曲表头固定为 `# | 歌曲 | 收藏 | 艺术家 | 专辑 | 评分 | BPM | 时长`。只保留一个 `TrackList.qml`；播放列表、标签筛选和资源文件夹页面只改变 `LibraryFilterModel` 的过滤条件。颜色、圆角、间距、描边和选中态进入 `Theme.qml` 语义 token，不在页面散落色值。深色参考色以近黑蓝背景、紫灰边线、暖白正文、棕金次要文字和低饱和深紫选中态为准；浅色主题保持现有语义并验证对比度。

## 4. 标签目录与筛选

新增 `TagModel : QAbstractListModel`，角色最少包括规范名称、显示名称、歌曲数量、颜色和是否选中。它以现有 `TrackRecord::tags` 为歌曲关联真值，并使用现有 AppData/QSaveFile 持久化约定保存很小的标签目录元数据（空标签及显式颜色）；不建立数据库。

首次加载允许对内存中的 `LibraryModel` 做一次聚合，之后通过 `rowsInserted`、`rowsAboutToBeRemoved`、`TagsRole dataChanged` 和模型重置事件增量维护计数。`LibraryModel::setTags` 增加明确的旧/新标签变更信号；重命名和删除使用批量 API，只对受影响行发出 `dataChanged`，最后合并为一次持久化请求，不重新扫描音频或重置全模型。

标签大小写无关去重，显示名保留用户输入。添加标签可暂时为零首歌曲；重命名保留原颜色；删除仅删除标签及歌曲关联，不删除歌曲或音频文件。删除当前筛选标签时自动清空标签筛选并保持搜索、评分、BPM 等其他条件。

`LibraryFilterModel` 新增单一标签过滤条件，与搜索、评分、BPM、歌单/文件夹范围组合使用。标签点击只更新过滤条件并触发代理模型过滤，不导入、不扫描、不分析波形。

右栏使用虚拟化 `GridView`，固定三列。顶部只显示搜索框和添加标签；低频操作通过按需打开的统一 ContextMenu 提供重命名、删除和修改颜色。长名称省略并提供 tooltip。标签色板与歌曲波形 36 色板完全独立；颜色持久稳定，计数只更新受影响标签。

## 5. 左侧导航与资源文件夹

左侧继续复用现有歌单、收藏和媒体库能力，并以一个扁平、可虚拟化的 `LibraryNavigationModel` 表达层级节点。角色包含节点 ID、类型、深度、显示名、数量、展开状态和可执行操作。界面只创建可见 delegate；展开/收起通过 `rowsInserted`/`rowsRemoved` 改变当前节点的可见子区间，不重建整棵树。

展开图标语义统一为：`＞` 表示可展开但未展开，`∨` 表示已展开；触发收起后回到 `＞`。不额外引入第三种持久状态图标。我的音乐库显示总数，二级分类显示各自数量，收藏显示收藏数，标签管理显示 TagModel 的标签总数。

资源根目录继续由 `LibraryManagerController` 管理。添加只保存目录引用并调用现有后台扫描；移除只删除 AgPlayer 引用和 watcher，不删除磁盘目录或音频。子目录在首次展开时按需生成一层节点，目录统计来自已导入 Track 路径索引并随歌曲插入/移除增量更新，不在 GUI 线程递归扫描。

从系统文件管理器拖入资源文件夹区域时，现有 drop 路由区分目录与音频文件：目录校验后加入监控根并异步扫描；普通音频仍走现有导入链。失败或取消不改变文件、歌单、标签或监控目录。

## 6. 真实轻量波形缩略图

新增两个职责单一的类型：

- `TrackWaveformThumbnailProvider`：低优先级、cache-only、异步读取已有 `.agwf` v2 mix Peak；缓存命中后按连续时间桶保留峰值，降采样和量化为固定 128 bytes。缓存未命中直接返回无数据，绝不调用 `ag_track_analysis_with_aggregation`。
- `TrackWaveformThumbnailItem : QQuickItem`：接收 128-byte `QByteArray` 和颜色，用一个 `QSGGeometryNode`/`QSGGeometry` 绘制 128 个对称静态线段；只有歌曲、Peak、宽高变化时重建几何，颜色变化只更新材质。

Provider 使用最大 256 首的有界 LRU，并对同一 Track ID 的并发请求去重；工作线程最多一个且复用 Qt 线程池，不建立常驻扫描线程。读取、降采样和量化都在 GUI 线程之外；回调携带 Track ID/请求代际，delegate 复用后不会显示上一首歌曲的结果。

彩色模式使用文档给定的固定 36 色表。对持久 `trackId` 做 FNV-1a 32-bit，再 `% 36`；不得依赖 row index、随机数或进程随机 Hash。纯色模式只改变渲染颜色，不重新读取 Peak 或重建几何。

`TrackList` 标题单元使用条件 `Loader`。`listWaveformThumbnailEnabled=false` 时不实例化 Item、不请求 Provider、不读取缓存、不计算颜色、不创建 Node/Geometry，并把行高恢复为 42。开启时只为可见 delegate 创建 Item；缓存未命中显示空白或 1px 静态基线，等待主播放器或既有预取以后产生缓存再刷新。

主播放器 `WaveformProvider`、`WaveformItem`、进度、Seek、hover、BPM 和播放速度逻辑保持原样；列表颜色不传给主播放器。

## 7. 设置与即时生效

在现有 `SettingsController` 和设置保存文件中加入：

- `listWaveformThumbnailEnabled`，默认开启。
- `listWaveformThumbnailMode`，值为 `Color36` 或 `Mono`。

设置页放入“外观与波形 → 歌曲列表”。开关立即创建/释放当前可见 Loader；模式切换只更新颜色。主题切换时彩色模式不重新分配颜色，纯色模式只读取主题 mono token。恢复默认设置覆盖这两个属性，并由现有设置测试验证迁移、持久化和复位。

## 8. 拖拽预览

复用 `TrackList` 现有 Drag/MIME 数据和排序链路。拖动开始时用实际封面和歌曲名创建一次轻量预览快照，透明度限定 0.60–0.75；多选显示首个封面和“已选择 N 首”。拖动期间只更新位置，不重新截图、读封面、请求波形或运行动画。取消或失败时释放预览且不改变数据。

歌单、标签与资源目录目标继续通过 Qt Drag & Drop/QMimeData 处理，不加入平台专属拖放实现。只有为接收 Windows/Qt 系统目录拖放所需的命中位置路由可扩展 `NativeDropRouter`，既有文件导入行为不得回归。

## 9. 错误处理与兼容

- 旧曲库没有标签目录元数据时，从现有歌曲 tags 构建目录，不改写音频文件。
- 标签目录文件损坏时保留歌曲内 tags，并重新构建缺失目录；不清空曲库。
- 波形缓存损坏、过期或缺失时显示空态并记录可诊断状态，不触发列表分析。
- 资源目录不存在时标记不可用；移除引用不删除磁盘数据。
- 所有异步结果必须验证对象生命周期、Track ID 和请求代际。
- 所有新 C++ 使用 C++17、RAII、const correctness；无第三方依赖和平台私有绘制。

## 10. 测试与视觉验收

开发遵循红—绿—重构。最小自动测试覆盖：

- TagModel 初次聚合、增量计数、空标签持久化、重命名保色、删除解除关联、不删除歌曲。
- LibraryFilterModel 的标签与搜索/评分/BPM/歌单/文件夹组合过滤，不发生全模型 reset。
- 导航节点展开/收起、增量数量、资源根持久化、移除引用不删除真实目录、后台目录导入。
- 128 桶下采样的静音、端点、瞬态峰值、非有限值和确定性；cache hit 不分析，cache miss 不分析。
- 36 色映射跨排序/搜索/重启稳定；纯色切换不读取 Peak。
- Loader 关闭时不存在 Thumbnail Item，Provider 请求计数为零；开启时 delegate 复用无串图。
- 单个缩略图只有一个 Scene Graph Node，geometry/vertex buffer 复用，播放进度不会触发 update。
- 单首/多首拖动、取消、允许目标和一次性预览。

运行验收包括 1000/10000 首列表快速滚动、排序、搜索、歌单/标签/文件夹切换；同时播放无损音频、Seek、切歌和滚动，确认无卡音、爆音或主波形回归；检查功能关闭前后 CPU、内存、磁盘 I/O 和 GPU 节点数量；检查 Dark/Light、100%/125%/150%/175%/200% DPI。

视觉验收必须在 1447×1087 参考状态下抓取真实 AgPlayer 窗口，统一裁剪和密度后把参考图与实现截图放入同一比较输入。字体、间距、颜色、图像质量、文案、列宽、行高、三列标签和滚动状态逐项检查。所有 P0/P1/P2 修正并重新截图，项目根目录 `design-qa.md` 最终结果必须为 `passed`；P3 可记录为后续精修。

## 11. 需求追溯与明确不做

实现计划必须把文档第 1–40 节分别映射到以下工作包：共享歌曲列表与过滤、标签目录与管理、左侧导航/资源目录、cache-only 128 Peak、Scene Graph Item、36 色稳定映射、设置零实例、拖拽预览、性能/播放/主题/DPI/视觉验收和开发记录。

明确不做：修改播放核心、Audio Callback、主波形时间映射或颜色设置；列表缓存未命中自动分析；启动时全库波形扫描；为波形新增图片/数据库/缓存目录；把标签页、歌单页、文件夹页复制为三张歌曲表；为像素还原引入 Shader、Glow、Blur、动画或新依赖。
