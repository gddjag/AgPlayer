# AG Player《音频编辑》V2 重构设计规格

**日期：** 2026-08-12

**状态：** 用户已批准

**目标：** 在现有 Qt 6 / QML / C++17 / FFmpeg 工程内，以原生轻量单轨《音频编辑》完整替换旧《轻度剪辑》多轨模块。

## 1. 决策优先级

1. 用户本次文字指令优先于参考图和 V3 文档中的冲突内容。
2. 顶部音频工具固定顺序为：`音频编辑 / 格式转换 / 元数据修改 / 文件名处理`。
3. 参考图决定《音频编辑》页面的布局、信息密度和视觉层级，不作为背景贴图，不照搬第三方资源。
4. 新模块完成并通过验收前，不删除旧模块；切换入口后再清理旧代码、资源、测试和构建项。
5. 本轮不封装 EXE。构建和自动化测试不等于真实 UI、硬件录音、播放、处理与导出验收。

## 2. 已确认现状

- 目标工作树：`D:/ai/AgPlayer/.worktrees/revised-ui`，分支 `codex/revised-ui`。
- 保留用户已有未提交修改：`PlayerPane.qml`、`TrackList.qml`、`tst_main_window.qml`。
- Release 基线构建在加载 Visual Studio 2022 开发环境后通过。
- 基线测试：60 项中 56 通过；既有失败为中文翻译 unfinished、主窗口 QML 超时、旧轻度剪辑 QML 失败、旧布局契约失败。
- 当前安装目录基线约 111.32 MiB；最终只比较同一构建与打包口径下的增量。
- 旧 `LightEditor` 控制器约 4,000 行，包含轨道、片段、交叉淡化、工程保存和混音等多轨职责。
- 旧 `multitrack_edit` 会把编辑内容大范围装入内存，不满足两小时文件和低内存目标。

## 3. 范围

### 3.1 必须交付

- 单声道/立体声单轨文档，一个时间轴和一个活动选区。
- 打开、拖入、新建录音、插入到光标、播放、Seek、循环选区。
- 剪切、复制、粘贴、删除、裁剪、静音、插入静音、淡入、淡出、增益、峰值归一化。
- 撤销/重做，编辑历史不复制完整源文件。
- 文件摘要、中央波形、时间标尺、标记、播放头、选区、缩略导航、Transport、状态栏。
- Windows WASAPI 原生录音、设备能力、电平、监听、暂停/继续、停止、Finalizing、恢复。
- BPM 检测、手动 BPM、目标 BPM、速度、保持音调、半音/音分、实时预览、后台应用。
- 事务式保存、另存为、完整文档/选区导出、取消、真实进度和动态参数校验。
- 快捷键、焦点、Tooltip、可访问名称、结构化错误、多语言和设置持久化。

### 3.2 明确不做

- 多轨、混音器、轨道头、工程总线、MIDI、VST/AU、自动化、频谱修复、AI 降噪和云服务。
- macOS Core Audio 与 Linux PipeWire/ALSA 的伪实现。未实现平台在构建和 UI 中明确关闭。
- Qt Multimedia 录音、QML Canvas 全波形、完整文件载入 RAM、直接覆盖源文件。

## 4. 架构

采用“纯 C++ 单轨域核心 + Qt 边界控制器 + QML 展示”的三层结构。外部主接口保持小而稳定，复杂状态、任务调度和失败回滚隐藏在深模块实现内。

### 4.1 `AudioDocument` 深模块

**接口职责：** 打开/新建文档、查询摘要和选区、提交编辑命令、撤销/重做、生成只读渲染快照。

**内部模型：**

- `SampleFrame = int64_t` 为唯一主时间坐标。
- `AudioSource` 引用不可变源文件或恢复文件。
- `AudioSpan` 描述源区间、静音区间或已渲染区间。
- `Selection` 使用 `[startFrame, endFrame)`，边界始终落在整数采样帧。
- `EditCommand` 只记录 Span/参数变化；提交失败时文档保持原状态。
- 标记随插入、删除和裁剪按统一规则移动或删除。

禁止在公开接口暴露轨道、片段、lane、mixer 或旧工程模型。

### 4.2 `EditorViewport` 深模块

**接口职责：** 在帧、逻辑像素、可见范围和缩放倍率之间统一转换，并驱动主波形与缩略导航双向同步。

- 主波形、缩略波形、标尺、播放头、选区和标记共用同一个映射。
- 缩放围绕鼠标或播放头；右栏折叠和窗口伸缩只改变视口宽度，不改变音频坐标。
- 复用现有波形分析、缓存和 `QQuickItem` Scene Graph 渲染，新增多级峰值金字塔；缩放不重新扫描整文件。

### 4.3 `EditorActions` 深模块

**接口职责：** 向 QML 暴露稳定 Action ID、文本、图标、快捷键、enabled/checked/busy 和统一触发入口。

- 工具栏、菜单和快捷键使用同一 Action。
- enabled 状态由文档、播放、录音、处理、保存状态联合计算。
- QML 不重复业务判断，不直接修改文档。

### 4.4 `RecordingSession` 深模块

**接口职责：** 设备枚举、预检查、开始、暂停、继续、停止、Finalizing、取消和恢复。

- Windows adapter 使用 WASAPI Shared Event-Driven。
- 音频回调只写入预分配 SPSC 环形缓冲，不做磁盘 I/O、动态分配、普通锁等待或 UI 更新。
- Writer 线程写临时录音源；`RecordingJournal` 支持异常退出恢复。
- 顶部“新建录音”和底部“录音”共用同一预检查与状态机。
- 右侧模式单选只配置“新建录音/插入到光标”，不打开设备或开始录音。
- 录音输出格式/目录独立于文档导出参数，默认 WAV PCM 24-bit；目录无效时禁止开始，不静默改存。

### 4.5 `TimePitchSession` 深模块

**接口职责：** BPM 分析、参数联动、实时预览、应用、取消和延迟报告。

- 复用现有 BPM、SoundTouch、预览播放和后台任务基础设施。
- 目标 BPM 与速度百分比双向联动；半音与音分组合为音高比率。
- 参数变化只改变 PreviewGraph，不修改文档。
- “应用处理”离线渲染到临时源，成功后以一个可撤销命令提交。
- Seek 时 reset 处理器，播放头按处理延迟补偿。

### 4.6 `DocumentWriter` 深模块

**接口职责：** 校验保存/导出请求、渲染、验证输出并原子提交。

- 同目录临时文件、flush、关闭、重新探测/解码校验、原子替换。
- 导出完整文档或选区；编码器参数来自当前 FFmpeg 构建能力。
- 不静默改变采样率、位深、声道、编码器或质量。
- 失败和取消删除临时输出，不损坏原文件，不显示成功。

## 5. UI 设计

### 5.1 页面结构

从上到下、从左到右固定为：

1. 顶部工具导航：`音频编辑 / 格式转换 / 元数据修改 / 文件名处理`。
2. 命令栏：打开、新建录音、保存、撤销、重做、剪切、复制、粘贴、删除、裁剪、静音、淡入、淡出、更多；导出靠右。
3. 中央列：单行文件摘要、主波形、缩略导航。
4. 右栏：仅“录音”“速度与音高”，可折叠。
5. 底部：Transport 控制带和状态栏。

禁止左侧常驻文件信息、标签、标记或轨道栏。标签编辑跳转《元数据修改》；标记列表仅按需弹出；导出使用独立对话框。

### 5.2 响应式规则

- 支持 1280×720、1600×900、2560×1440、3840×2160 和高 DPI。
- 主波形永远获得剩余空间；右栏宽 288–320 logical px，最大 344 px。
- 狭窄窗口按优先级隐藏摘要低优先字段，文件名和时长不隐藏、不换行。
- 页面不得出现横向滚动条；4K 不使用固定 3840×2160 坐标。
- 所有显示值来自真实状态；空文档显示明确空态，不展示 Demo 文件、设备、BPM 或时长。

### 5.3 视觉验收

- 使用现有深色主题、图标体系、间距和强调色。
- 截图与参考图比较整体层级、区域占比、主波形宽度、右栏内容和控件顺序。
- 视觉相似不代替交互验证；所有可见按钮必须有真实行为或正确禁用。

## 6. 数据与状态流

```text
文件/录音源
  → AudioDocument(Span 时间线)
  → EditorViewport + Peak Pyramid
  → EditorActions / QML
  → Playback Preview 或 Offline Render
  → DocumentWriter 临时文件
  → 完整校验
  → 原子提交
```

互斥状态由一个顶层 `EditorSessionState` 汇总：Empty、Ready、Playing、Recording、RecordingPaused、Finalizing、Previewing、Processing、Saving、Exporting、Error。状态切换失败不得留下半提交文档。

## 7. 复用与删除

### 7.1 复用或抽取

- FFmpeg 解码/编码/重采样、格式探测和转码能力。
- 波形分析、波形缓存、Scene Graph 波形渲染。
- 播放器输出与音频预览控制器。
- BPM 分析、SoundTouch 时间/音高处理。
- 任务取消、设置、日志、多语言、文件发现、拖入和元数据探测。

复用前必须验证其内存、线程、错误和授权行为；不合格部分只抽取底层能力。

### 7.2 最终删除

- `LightEditPage.qml`、`MultiTrackWaveform.qml` 及旧多轨专用 UI。
- `light_editor_controller.*` 中的轨道/lane/clip/交叉淡化/工程保存职责。
- `multitrack_editor.*`、`timeline_preview_mixer.*` 及对应 C API。
- 旧多轨测试、翻译、设置、图标、QML 注册、CMake/qrc 条目和无引用代码。

只有新模块验收通过后执行删除；公共能力先迁移并由新测试覆盖。

## 8. 实施分解与门禁

1. **基础门：** 修复与本模块验收直接相关的基线失败，建立回退记录与精确体积基线。
2. **单轨文档：** SampleFrame、Source/Span、Selection、Command/Undo、事务式编辑。
3. **波形时间线：** 峰值金字塔、统一映射、主波形、选区、标记、缩略导航。
4. **UI 骨架：** 新页面、指定导航顺序、命令栏、摘要、右栏、Transport、状态栏。
5. **保存导出：** 独立 ExportDialog、验证、取消、原子提交。
6. **Windows 录音：** WASAPI、环形缓冲、Writer、Journal、统一状态机和真实设备 UI。
7. **BPM/速度/音高：** 分析、预览、延迟补偿、离线应用和撤销。
8. **切换与清理：** 未保存提示、入口切换、旧模块删除、全量回归与体积比较。

每一门先写失败测试，确认失败原因正确，再做最小实现；每门结束都构建、测试并记录结果。后续门不得用占位按钮冒充前一门完成。

## 9. 测试与验收

### 9.1 自动化

- 单元：帧/时间、映射、Span 编辑、选区、撤销/重做、BPM 比率、目标帧数、音高换算、环形缓冲、Journal、缓存失效、输出计划、导出校验。
- 集成：现有支持格式与采样格式、长文件、损坏/只读/占用/空间不足、Unicode 路径、取消、100 次撤销重做、处理后重开、录音错误和恢复。
- 音频正确性：正弦、脉冲、静音、左右不同信号、固定 BPM、人声/鼓点；验证样本边界、声道、NaN/Inf、时长、音高、尾音和可重解码。
- QML：导航顺序、布局契约、Action 状态、响应式尺寸、键盘、可访问性和真实空态。

### 9.2 实机

- 在真实窗口验证 1280×720 至 4K、高 DPI、右栏折叠和无横向滚动。
- 使用真实本地音频验证打开、波形、选择、剪辑、撤销、播放、Seek、处理、保存与导出。
- 使用真实麦克风验证设备枚举、电平、监听、录音、暂停/继续、停止、Finalizing、恢复文件和回放。
- 测量启动、首屏波形、完整峰值、缓存命中、内存、CPU、处理倍率、导出速度和模块体积增量。

## 10. 完成定义

只有以下全部满足才可宣称完成：

- 新模块功能与 UI 验收通过，旧《轻度剪辑》多轨代码和入口已清除。
- Release 编译零错误、零警告，全量测试通过。
- 真实 UI、音频播放、录音、处理、保存和导出均有当次证据。
- 原文件安全、失败提示真实、无不可用占位控件、无未实现平台伪能力。
- 同口径安装体积增量不超过 5 MiB；超出时给出逐项分析并继续裁剪。
- 提供删除清单、性能数据、第三方许可、操作说明、回归报告和未完成项。

## 11. 回退策略

- 开始生产代码前记录当前提交、工作树状态和用户未提交修改文件。
- 新代码独立放入 `AudioEditorV2` 路径，通过入口开关与旧模块隔离。
- 每个阶段保持可构建、可测试；不把用户现有修改混入阶段提交。
- 清理旧模块前建立最后回退点；清理提交必须与功能提交分离。
