# AgPlayer 第一阶段 Windows 播放 MVP 设计规范

**状态：** 已确认  
**确认日期：** 2026-07-22  
**设计基准：** `播放页确定.jpg`、`迷你播放器.jpg`、两份透明 Logo 与 `开发要求.txt`

## 1. 目标

第一阶段交付一个真实可用的 Windows 音频播放闭环：用户导入本地音频后，程序在后台读取元数据和封面、生成真实波形缓存，并完成播放、暂停、上一首、下一首、波形 Seek、音量、循环、收藏、歌曲列表以及迷你播放器切换。

界面使用 Qt 6 / QML，业务实现使用 C++17。FFmpeg 负责解码和媒体信息读取，miniaudio 负责音频设备输出。播放与波形核心必须不依赖 Qt，通过窄接口供 Qt Bridge 调用，以便后续桌面端复用并为 HarmonyOS 的 C/NAPI 接入保留清晰边界。

## 2. 项目级硬约束

- 工作目录为 `D:\ai\AgPlayer`，从空项目开始。
- 第一阶段优先支持 Windows；macOS、Linux 和 HarmonyOS 不在本阶段构建范围内，但核心代码不得依赖 Windows UI 或 Qt 类型。
- 使用 Qt 6.7、QML、C++17、CMake 和 CTest。
- 第一阶段只接入 FFmpeg 与 miniaudio。SoundTouch 与 kissfft 在真正需要变速变调和频谱分析的后续阶段再接入。
- 每个可见控件必须具有真实功能；未完成的设置、磁吸窗口和音频工具入口不得作为假按钮出现。
- 编译必须零错误、零警告；测试失败或视觉高、中优先级差异未修复时不得进入第二阶段。
- 不封装、不部署、不生成发行 EXE。只有用户明确要求后，才允许执行最终打包。
- 不在第一阶段创建未来功能的空类、空页面、工厂或单实现接口。

## 3. 第一阶段范围

### 3.1 包含

- 拖拽导入和文件选择器批量导入本地音频。
- MP3、WAV、FLAC、AAC、M4A、OGG、Opus、WMA 的媒体信息读取与播放验证。
- 标题、艺术家、专辑、格式、采样率、位深、码率、时长、文件大小和内嵌封面读取。
- 播放、暂停、上一首、下一首、当前队列、顺序循环、单曲循环和随机播放。
- 音量调整、静音、收藏以及应用重启后的音乐库状态恢复。
- 真实离线波形分析、缓存、播放进度覆盖、点击/拖拽 Seek 和悬浮时间提示。
- 主播放界面和迷你播放器；两者共享播放实例和所有播放状态。
- 当前阶段可用的歌曲列表：选歌、播放状态、收藏和基本元数据展示。
- 运行日志和面向用户的可恢复错误提示。

### 3.2 不包含

- 列表独立窗口、四向磁吸、联动拖拽和贴边隐藏。
- 完整设置页、主题切换、快捷键编辑和缓存管理界面。
- 搜索、评分、BPM 筛选、10,000 首分页模型和歌词窗口。
- 纯色波形/动态频谱的用户切换入口；第一阶段固定交付参考图中的 RGB 渐变波形。
- 格式转换、剪辑、BPM 调速和升降调工具。
- 全局媒体快捷键、系统文件关联、自动更新和安装程序。
- macOS、Linux、HarmonyOS 的构建产物。

这些能力分别进入第二、第三和最终发行阶段；在实现前不显示对应入口。

## 4. 方案选择

采用“纯 C++17 音频核心 + Qt Bridge + QML UI”三层架构。

未采用 Qt Multimedia 直接播放，因为它会把核心播放链路绑定到 Qt，且不利于精确控制 Gapless、PCM 缓冲和 Seek 延迟。未采用全 FFmpeg 设备输出，因为实时控制链路更复杂、更重，不符合轻量目标。

## 5. 架构与责任边界

### 5.1 纯 C++17 核心

核心只接收标准 C++ 类型，不包含 `QObject`、`QString`、`QImage`、`QThread` 或 QML 依赖。

- `Decoder`：使用 FFmpeg 打开文件、读取媒体信息、解码为统一 PCM 帧，并执行时间定位。
- `AudioEngine`：维护解码器、PCM 环形缓冲和 miniaudio 输出设备；音频回调中不得分配大对象、访问磁盘或等待锁。
- `PlaybackSession`：维护当前队列索引、播放状态、循环模式、音量、静音和播放位置，是播放状态的唯一真实来源。
- `WaveformAnalyzer`：离线分块解码音频并生成归一化峰值数据；支持取消和进度报告。
- `WaveformCache`：按规范化路径、文件大小、最后修改时间和分析版本生成稳定缓存键；使用临时文件加原子替换避免半写入缓存。
- `MediaMetadata`、`TrackId`、`PlaybackSnapshot`、`CoreError`：核心与适配层之间使用的值类型。

本阶段优先提供稳定的 C++ 接口。对外 C ABI/NAPI 包装将在 HarmonyOS 阶段基于同一接口薄封装，不提前维护一套当前没有消费者的绑定代码。

### 5.2 Qt Bridge

- `PlaybackController`：把 QML 命令转换为核心调用，以 Qt 属性和信号发布不可变播放快照。
- `LibraryModel`：使用 `QAbstractListModel` 暴露第一阶段歌曲列表角色，保存收藏和队列状态。
- `ImportController`：接收拖拽或文件选择结果，在后台读取元数据，并逐条提交到模型。
- `WaveformItem`：自定义 `QQuickItem`，通过 Scene Graph 节点渲染峰值、RGB 渐变、已播放区和指针位置；不在 QML 中拼装成千上万个矩形。
- `WindowController`：在主播放器和迷你播放器之间切换可见窗口；不创建第二个播放实例。
- `LibraryStore`：使用 Qt Core 自带 JSON 和 `QSaveFile` 原子保存音乐库，不新增数据库依赖。数据读取在工作线程完成，完成后一次提交模型。

Qt Bridge 不执行实际解码、DSP 或设备输出。

### 5.3 QML 界面

- `MainWindow`：参考 `播放页确定.jpg`，第一阶段将播放区与歌曲列表放在同一窗口中。
- `PlayerPane`：封面、标题、艺术家、专辑、媒体标签、波形、时间和主要播放控件。
- `TrackList`：虚拟化歌曲行、当前播放状态、收藏和基础元数据。
- `MiniPlayerWindow`：参考 `迷你播放器.jpg`，支持置顶、恢复主窗口、最小化和关闭。
- `Theme`：集中定义 `#0A0A0F` 背景、`#00D4FF` 到 `#7B2FF7` 品牌渐变、间距、圆角、字体层级和控件状态。

图标优先使用 Qt 可合法分发的统一图标资源或项目内统一图标集，不用文字字符、Emoji、临时矩形或手绘占位符代替。Logo 直接使用用户提供的透明 PNG。封面优先使用音频内嵌封面；没有封面时使用用户提供的品牌 Logo 作为明确的默认图，而不是伪造专辑封面。

## 6. 状态与数据流

### 6.1 导入

1. QML 把文件 URL 列表交给 `ImportController`。
2. 后台任务规范化并去重路径，逐个调用核心元数据读取。
3. 成功结果增量提交 `LibraryModel`，失败结果携带具体原因返回；单个失败不终止批次。
4. 可播放歌曲立即进入队列；波形分析在低优先级后台任务中启动。
5. 模型变更经短间隔合并后由 `LibraryStore` 原子保存，避免每导入一首都同步写盘。

### 6.2 播放

1. QML 只向 `PlaybackController` 发送命令，不自行推断播放状态。
2. `PlaybackSession` 选择曲目，`Decoder` 预填 PCM 环形缓冲，然后 `AudioEngine` 启动设备。
3. 核心定期发布 `PlaybackSnapshot`；Bridge 在 GUI 线程合并并更新 Qt 属性。
4. 主界面和迷你播放器绑定同一组属性，因此切换窗口不重建解码器、不丢失进度。

### 6.3 Seek

1. 波形点击或拖拽产生目标时间；拖拽时界面先显示预览位置。
2. 用户提交后，核心暂停消费旧缓冲、清空 PCM、执行 FFmpeg Seek、解码至目标时间并重新填充缓冲。
3. 第一批目标 PCM 可用后恢复输出并发布实际位置。
4. 性能计时从提交 Seek 命令到首个目标音频采样进入输出回调，统计 P95。

### 6.4 波形缓存

1. 命中有效缓存时立即加载峰值数据。
2. 未命中时后台分析并发布真实进度。
3. 源文件大小或修改时间变化、分析格式升级时缓存自动失效。
4. 缓存不可写时保留内存结果；缓存失败不得中断播放。

## 7. 线程模型

- GUI 线程：QML、Qt 模型提交和 Scene Graph 状态交换。
- 音频设备线程：只读取预先准备的 PCM 并写入设备。
- 解码线程：持续填充 PCM 环形缓冲并处理 Seek 请求。
- 后台任务线程：元数据读取、波形分析和音乐库持久化。

线程之间使用有界缓冲、原子状态或短临界区。音频回调不记录普通日志、不访问 UI、不执行文件 I/O，也不等待后台任务。

## 8. 界面与交互设计

- 以 1448×1086 的主界面参考图为视觉基准，保持顶部播放区、中央波形和底部列表的相对比例；窗口缩放时优先压缩列表高度，不挤压主要播放控件。
- RGB 波形从青蓝过渡至紫色和洋红色，已播放位置、悬浮指针和时间提示必须来自真实播放位置。
- 播放/暂停按钮是视觉焦点，具有参考图中的渐变描边和柔和光晕，同时提供清晰的 hover、pressed、focus 和 disabled 状态。
- 标题和元数据过长时使用省略与悬浮完整提示，不覆盖右侧控件。
- 空音乐库显示可操作的导入引导；导入中显示真实进度；导入失败显示文件名和原因。
- 迷你播放器保持毛玻璃感和圆角轮廓；若当前系统组合下透明模糊不可用，则使用同色半透明背景和细边框作为稳定降级，不牺牲文字可读性。
- 主窗口关闭时停止播放并安全退出；迷你窗口关闭等同于关闭应用；恢复按钮返回主窗口；置顶按钮立即改变窗口置顶状态。

## 9. 异常与恢复

- 损坏、不支持或无权限访问的文件：记录精确错误、从当前批次跳过并继续导入其他文件。
- 源文件被移动或删除：保留音乐库记录并标记不可用；选择时提示重新定位或移除。
- 输出设备断开：停止向失效设备写入并安全暂停，刷新设备列表后允许用户重试；不得崩溃或无限重连。
- 解码失败：停止当前曲目并报告原因；根据当前循环模式决定是否允许用户手动切到下一首，不自动形成失败循环。
- 缓存损坏：删除单个损坏缓存并重新分析；无法写入时退回内存结果。
- 后台任务取消和应用退出：停止接收新任务，取消可取消任务，等待已进入原子写入阶段的任务结束，再关闭音频设备和线程。

## 10. 测试与质量门禁

### 10.1 自动化测试

- C++ 单元测试：播放状态机、循环模式、队列边界、PCM 环形缓冲、缓存键、缓存失效、取消、错误映射和 Seek 状态转换。
- 核心集成测试：用短小且可再分发的真实音频夹具验证 FFmpeg 打开、解码、时长、位置和波形峰值。
- 格式验证：使用真实 MP3、WAV、FLAC、AAC/M4A、OGG、Opus、WMA 文件验证导入、播放、暂停、切歌和 Seek。
- Qt/QML 测试：导入结果、列表角色、可见控件、焦点、主/迷你状态同步和窗口切换。
- 失败路径：损坏文件、空文件、只读缓存目录、文件丢失、设备初始化失败和取消波形分析。

### 10.2 视觉与交互 QA

- 在与参考图相同的视口和播放状态下捕获应用截图，与原图并排比较。
- 检查布局、间距、字体、颜色、圆角、图标、封面裁切、波形位置和各控件状态。
- P0/P1/P2 差异必须修复并重新截图比较；P3 只允许记录为后续细节优化。
- 逐个点击所有可见控件，并验证其状态变化确实来自核心状态。

### 10.3 性能与真实播放

- Seek 从提交到目标采样输出的 P95 小于 20ms；记录测试文件、设备、次数和统计结果。
- 后台波形分析期间持续播放并操作界面，不出现爆音、明显掉帧或主线程长阻塞。
- 在本机扬声器或耳机连续播放，反复执行快速切歌、拖动进度、音量和迷你模式切换。
- 使用调试工具检查线程退出、句柄、内存增长和崩溃。
- 全目标以严格警告级别编译，并把警告视为错误。

## 11. 第一阶段完成定义

只有同时满足以下条件才算完成：

- 第一阶段所有范围项均为真实实现，没有可见假按钮或静态伪数据。
- 全量自动化测试通过，编译零错误零警告。
- 真实格式与本机音频设备测试通过。
- Seek、播放稳定性和界面响应达到本规范门槛。
- 主界面和迷你播放器视觉 QA 的 P0/P1/P2 问题已修复。
- 退出无残留进程，音乐库和缓存写入可恢复。
- 未运行任何 EXE 打包或部署流程。

第一阶段完成后向用户报告测试数量、真实格式、视觉差异、性能数据和未进入本阶段的后续功能；经用户确认后才规划第二阶段。
