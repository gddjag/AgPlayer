## 目标

在不重写播放核心、不回退频彩波形成果、不引入大型依赖的前提下，完成以下 11 项修复，并为每项建立可自动验证的合同：

1. 迷你播放器移除歌词入口，把播放模式放到音量左侧。
2. 缩小 18 段 EQ 窗口，同时保持现有文字字号和清晰度。
3. Windows 安装界面不再询问语言，默认中文。
4. 五个音频工具页面的顶部切换项统一左对齐。
5. 单窗口、双窗口的播放组件按参考图排序，歌词图标与同级图标等大。
6. 音频文件信息改为紧凑竖版小窗口。
7. 修复 Windows 任务栏图标单击时的显示、隐藏和激活交互。
8. 设置页把“深色（默认）”改为“深色”。
9. 语言设置只保留中文和英文，去掉语言名称前的 CN/US 或旗帜标记。
10. 自动搜索匹配歌词，至少三条免费线路，线路故障时自动切换并明确提示。
11. 优化播放进度色，使波形进度连续、平滑，不再按峰值桶跳动。

## 非目标与全局约束

- 不改变音频解码、播放队列、EQ DSP 参数、频彩波形低中高频 Mix 算法或已播放颜色语义。
- 不用空壳按钮、模拟网络响应或硬编码歌词冒充功能完成。
- 不在播放热路径增加网络访问、磁盘扫描或高频分配。
- 不新增常驻后台服务；歌词请求只在需要时运行并支持取消。
- 不把本地音频路径、音频内容或用户目录上传给歌词服务；只发送匹配所需的标题、艺术家、专辑和时长。
- 所有主题继续消费共享 `Theme` 令牌和共享业务组件，避免为深色、浅色、跟随系统复制功能代码。后续修改共享组件即可同步到各主题。

## 播放组件与图标合同

### 迷你播放器

底部播放控制从左到右为：

`波形显示方式 → 上一首 → 播放/暂停 → 下一首 → 播放模式 → 音量`

迷你播放器不显示歌词入口，也不显示“切换到单窗口”或“开启沉浸视觉”入口；窗口外层原有的列表、主题、窗口模式等非播放区入口保持现状。实现上继续复用共享动作组件，通过显式可见性和布局参数表达变体，不复制整套按钮逻辑。

### 集成单窗口

播放组件从左到右为：

`播放列表 → 音频工具 → 18 段 EQ → 波形显示方式 → 上一首 → 播放/暂停 → 下一首 → 播放模式 → 歌词 → 音量 → 主题 → 沉浸视觉 → 窗口切换`

### 双窗口

播放器中央控制从左到右为：

`18 段 EQ → 波形显示方式 → 上一首 → 播放/暂停 → 下一首 → 播放模式 → 音量`

播放器右侧操作从左到右为：

`音频工具 → 歌词 → 主题 → 沉浸视觉 → 窗口切换`

歌词图标使用用户提供的歌词图形资源，视觉尺寸与相邻普通图标一致：普通布局目标 20 px，紧凑布局目标 16 px；点击热区仍满足现有最小交互尺寸，不以缩小热区换取视觉对齐。沉浸视觉入口同样使用用户提供的图形资源。

## 18 段 EQ 窗口

- 默认尺寸从约 `1000 × 600` 调整为约 `860 × 520`。
- 最小尺寸约为 `760 × 480`。
- 频点、增益值、标题等现有字号不缩小：频点约 14 px，数值约 12 px，标题约 20 px。
- 默认尺寸应完整显示 18 个频段；当窗口小于完整布局所需宽度时启用横向滚动，而不是压缩文字、滑杆或相邻点击区域。
- 预设、重置、启用状态和实际 DSP 连接保持不变。

## 音频工具顶部切换项

五个页面统一顺序：

`音频编辑 → 人声伴奏分离 → 格式转换 → 元数据编辑 → 文件名处理`

共享 `ToolSidebar` 取消导致居中的前置伸缩占位，仅保留尾部伸缩空间；按钮宽度、左边距、间距和选中态由同一组件统一提供。无论当前页面是哪一个，第一个切换项的 x 坐标必须一致。

## 音频文件信息窗口

- 右键“查看音频文件信息”使用约 `300 × 470` 的竖版紧凑窗口，不再使用横向大弹窗。
- 标签列宽按竖版重新分配，值区域允许换行或省略；本地长路径默认省略显示，但保留完整复制能力和可访问名称。
- 文件名、格式、时长、采样率、位深、声道、码率、大小、路径等当前可用字段不得因缩小窗口丢失；内容超高时使用纵向滚动。
- 曲库列表与资源管理器中同类信息窗口共享尺寸令牌和字段行组件，避免两套窗口再次偏离。

## 设置、语言与安装器

### 主题文字

设置页显示“深色”，英文显示“Dark”，不再附加“默认”字样。深色仍可保持内部缺省和非法值回退语义；本项只修改用户可见名称，不改变持久化枚举值。

### 应用语言

设置页只显示：

- `中文`
- `English`

删除泰语、越南语入口、运行时支持声明、构建注册和对应翻译目录，防止隐藏配置重新把它们带回界面。语言项前不显示 `CN`、`US`、国旗或其他地区缩写。已有用户配置为已删除语言时，启动后安全回退到中文。

### Windows 安装器

安装程序不显示语言选择对话框，交互界面直接使用中文。保留安装框架的语言资源和显式命令行语言参数兼容能力，但普通双击安装路径不再要求选择语言。

## 任务栏单击交互

先用真实 Windows Shell 复现并记录收到的原生消息，再做最小修复。高概率根因是无边框窗口缺少 Shell 识别所需的窗口样式，而不是 QML 按钮逻辑。

目标状态机：

- 主窗口在前台可见：单击任务栏图标，最小化该播放器窗口组。
- 主窗口已最小化：单击任务栏图标，恢复并激活。
- 主窗口在后台可见：单击任务栏图标，只置前激活，不先隐藏。
- 设置、EQ、歌词或音频工具窗口打开时，窗口组行为一致，不重复创建窗口。

优先在 `WindowController` 的原生样式与 `WM_SYSCOMMAND` 路径补齐 `WS_SYSMENU` / `WS_MINIMIZEBOX` 等 Shell 合同，同时保持无边框外观。禁止把所有 `WM_ACTIVATE` 事件映射为隐藏，因为这会破坏 Alt+Tab、通知弹窗和多窗口切换。验证覆盖经典双窗口、集成单窗口、100%/150% DPI 和双显示器几何保持。

## 波形播放进度平滑化

保留现有基底未播放层与已播放颜色层，统一改为连续像素裁剪：

`clipWidth = waveformWidth × clamp(position / duration, 0, 1)`

经典窗口和迷你播放器继续沿用双层裁剪；集成单窗口从单个 `WaveformItem` 的离散 `playedCount` 着色改为同一双层连续裁剪组件。`WaveformItem` 的峰值桶仍负责静态波形采样，不再决定可见播放边界。拖动、暂停、切歌、时长未知和回到 0 都必须稳定；不提高播放控制器的定时器频率，不在每帧重新分析波形。

## 免费歌词三线路架构

### 线路与许可边界

按以下顺序尝试网络线路：

1. **LRCLIB**：同步歌词优先，纯文本作为后备；项目/API 为免费开放能力。
2. **Unison**：同步或纯文本歌词；显示结果时保留明确的 `Lyrics from Unison` 署名，遵守其歌词语料许可和非商业使用边界。
3. **lyrics.ovh**：只作为纯文本应急线路；成功时提示“纯文本歌词，无时间轴”。

本地嵌入歌词、同目录歌词文件和本地缓存始终先于网络线路，不计入三条网络线路。不得增加付费线路、登录、API Key 或隐性收费代理。每条线路在实现前固定服务 URL、请求字段、响应格式、速率限制、许可证链接和署名要求，并在 About/歌词来源区域可查看。

### 模块边界

新增 `LyricsProviderChain : LyricsProvider`，继续复用现有 `LyricsService` 的搜索、匹配、缓存和取消接口。链内部组合：

- `LrclibProvider`
- `UnisonProvider`
- `LyricsOvhProvider`

统一结果结构增加 `providerId`、`providerName`、`sourceUrl`、`supportsSyncedLyrics` 和 `attribution`。`LyricsService` 不再硬编码来源名称，缓存同时保存歌词正文、时间轴能力、来源和署名；命中缓存时仍能正确显示来源。

### 匹配与回退

- 使用规范化后的标题、艺术家、专辑和时长搜索；精确匹配优先，再按标题/艺术家相似度和时长误差排序。
- 某线路返回 404 或正常的“无匹配”时，静默尝试下一线路，不把它误报为线路故障。
- DNS、TLS、超时、5xx、响应格式损坏属于技术故障：立即切换下一线路，并通过非模态提示指出失效线路和原因。
- 429 遵守 `Retry-After`，本次请求立即切换下一线路。
- 同一线路连续三次技术故障后熔断 10 分钟；冷却到期后允许一次探测恢复。
- 明确的纯音乐结果为终止成功，不继续从其他线路强找文本。
- 三条线路均失败时，结果面板逐条列出“无匹配 / 超时 / 限流 / 服务错误”等结论，并保留手动重试入口。
- 切歌或关闭歌词页时取消旧请求；迟到响应不得覆盖新歌曲。

### 用户提示与隐私

线路切换提示不阻塞播放。歌词页显示当前来源、是否有时间轴和必要署名；错误信息可复制但不暴露本地路径。网络请求日志只记录线路、HTTP 状态和耗时，不记录完整查询文本或本地文件信息。

## 数据流

1. 当前曲目变化后，歌词页生成带请求序号的查询。
2. `LyricsService` 依次检查嵌入歌词、同目录文件和缓存。
3. 本地无结果时调用 `LyricsProviderChain`。
4. Chain 跳过熔断线路，按顺序调用可用 Provider，并把技术故障转换为非模态通知。
5. 首个满足匹配阈值的结果返回 Service；Service 校验请求序号后写缓存并更新 QML。
6. 所有线路结束仍无结果时，Service 返回结构化汇总，不以空字符串伪装成功。
