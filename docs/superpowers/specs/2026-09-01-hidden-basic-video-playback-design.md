# AgPlayer 隐藏式基础视频播放能力设计规格

**日期：** 2026-09-01
**状态：** 方案 A 已确认，等待书面规格复核
**需求来源：** `AgPlayer_基础视频播放兼容能力_开发提示词.md`

## 1. 目标

在不改变 AgPlayer 音频播放器定位的前提下，为本地视频文件提供基础、
自动、轻量的播放兼容能力。用户通过 Windows 文件关联双击视频，或把单个
视频文件拖入现有播放器/播放列表后，播放器自动识别真实视频轨并显示画面，
不要求用户选择“视频模式”。

本功能复用现有播放队列、播放模式、上一首/下一首、暂停、Seek、音量、倍速
和播放状态。视频画面是当前音频播放会话的按需视觉伴随层，不是第二套播放器。

## 2. 产品边界

### 2.1 包含

- 本地 `MP4`、`MKV`、`WebM`、`MOV`、`AVI`、`M4V` 文件；实际编解码能力
  以应用随附 FFmpeg 的解码器为准。
- 含音轨视频和无音轨视频。
- 单个文件拖放、现有播放列表路径导入、命令行/文件关联启动。
- 无边框视频画面、基础控制栏、全屏、`Esc` 退出全屏、返回音频播放器。
- SDR 基础显示、旋转元数据、像素宽高比和等比留黑边。

### 2.2 不包含

- 视频模式、视频入口、视频分类、视频媒体库或文件选择器中的视频入口。
- 网络视频、字幕管理、视频编辑、滤镜、画质设置、HDR 色调映射或专业色彩管理。
- 播放列表缩略视频预览、视频封面抓取或后台视频索引。
- 新增 Qt Multimedia、VLC、mpv 或其他独立播放器框架。
- 本次交付中的安装包/发行 EXE；打包仍需另行授权并通过完整验收门禁。

视频条目可以作为普通媒体记录保存在现有资料库和播放列表中，但不会获得单独的
导航、筛选或媒体库页面。目录扫描和普通“导入音频”文件选择器继续只发现音频，
避免隐性扩大资料库范围；直接拖放、播放列表路径和文件关联打开的视频会被探测。

## 3. 已确认的交互决定

- 当前曲目包含真实视频轨时自动显示视频视图。
- 切换到纯音频曲目时自动恢复原播放器界面。
- 点击“返回音频播放器”时停止当前视频、退出全屏、释放视频资源并恢复音频界面。
- 停止后的当前视频再次被播放时，视频视图会重新自动出现。
- 设置为默认播放器之前不抢占系统文件关联；启用现有默认播放器设置后才注册
  支持的视频扩展名。

## 4. 方案选择

采用已确认的方案 A：现有 FFmpeg/miniaudio 音频核心作为唯一播放状态和主时钟，
按需挂载 FFmpeg 视频解码及 Qt Quick Scene Graph 呈现层。

拒绝 Qt Multimedia 双后端方案，因为它会复制播放状态、设备、队列、音量和倍速
语义，并增加部署模块。拒绝把现有核心整体重构为完整 A/V 引擎，因为隐藏式基础
能力不值得承担实时音频核心的大范围回归风险。

## 5. 架构

### 5.1 媒体探测与资料库记录

扩展现有 `MediaMetadata` 和 C ABI 元数据查询，记录：

- `has_audio`：是否存在可识别音轨；
- `has_video`：是否存在非 `AV_DISPOSITION_ATTACHED_PIC` 的真实视频轨；
- 视频宽、高和时长仅供验证/选择合理显示比例，不引入视频资料库字段集合。

`probe_media_metadata` 允许无音轨但有真实视频轨的文件成功导入：标题回退到文件名，
格式和时长从容器/视频轨取得，音频采样率、声道、位深和音频码率保持零。只有封面
图的视频流不得把音频文件标成视频。

`TrackRecord` 增加持久化的 `hasAudio`、`hasVideo`，并通过 `LibraryModel` 角色提供给
播放协调层。旧资料库缺少字段时按 `false` 读取；首次实际播放或元数据刷新时进行
受限补探测，避免旧数据永久误判。

### 5.2 唯一播放状态与静音时间轴

现有 `PlaybackController`、核心队列和 `PlaybackSession` 继续拥有：

- 当前媒体、队列索引和当前列表作用域；
- 顺序、单曲循环、随机、列表循环；
- Playing/Paused/Stopped/Error；
- position、duration、Seek、音量、倍速和上一首/下一首。

含音轨视频沿用现有 `Decoder` 和 miniaudio 输出。无音轨视频仅在播放器路径中启用
`allow_silent_video_clock`：以 48 kHz、双声道、全零采样生成受时长约束的静音块，
使现有状态机、位置、Seek、倍速和队列结束行为保持不变。音频编辑、波形分析、
格式转换和其他严格音频调用方不启用该选项，避免把无音轨视频伪装成可编辑音频。

### 5.3 视频解码 C ABI

在核心增加不暴露 FFmpeg 类型的同步视频解码 C ABI。接口负责：

- 打开本地路径并选择最佳真实视频轨；
- 读取下一帧，返回拥有明确生命周期的 RGBA/BGRA 像素、stride、PTS、显示尺寸、
  像素宽高比和旋转角；
- 按毫秒 Seek，并 flush codec；
- 通过现有 FFmpeg interrupt/cancel 机制及时结束阻塞读取；
- 销毁时释放 format/codec/frame/packet/sws 等所有资源。

接口只返回普通整数、字节缓冲和结构体，继续满足公开 C ABI 不泄漏 Qt/FFmpeg 类型
的项目约束。首版使用软件解码及 `libswscale` 转换；硬件解码不是本次范围。

### 5.4 Qt 视频协调层

新增一个 `VideoPlaybackController` 单例，依赖 `LibraryModel` 和
`PlaybackController`，但不拥有队列或独立播放状态机。

职责：

1. 在 `currentTrackId` 变化时读取 `hasVideo` 和路径。
2. 仅对真实视频创建一个解码工作线程；纯音频不创建线程、定时器或帧缓存。
3. 监听现有 `stateChanged`、`positionMsChanged`、`tempoChanged` 和成功 Seek 信号。
4. 以 `PlaybackController.positionMs` 为唯一主时钟，提前解码至有界队列。
5. 呈现不晚于当前时间的最新帧；丢弃明显过期帧，不通过延迟音频追赶画面。
6. Seek、切歌和退出使用递增 generation，旧线程/旧帧不能发布到新会话。
7. 暂停时保留当前帧并让解码线程等待；恢复后继续。
8. 解码失败时发布可见错误，但保持基础传输控制可用，允许返回或切歌。

不新增 16 ms 视频轮询器。帧呈现由现有播放位置通知和工作线程 `frameReady` 驱动。
队列上限为 3 帧且像素内存上限为 64 MiB；达到上限时工作线程等待。单帧超过上限
时只允许保留该单帧，不形成无界增长。

### 5.5 Scene Graph 呈现

新增 `VideoFrameItem`，通过 `updatePaintNode()` 在渲染线程创建和替换纹理：

- 工作线程只产生拥有独立存储的帧数据，不直接访问 QSG 对象。
- 纹理只在帧 generation/serial 变化时上传；普通属性变化不重复上传。
- 旧纹理在 Scene Graph 渲染线程释放。
- `releaseResources()`、窗口失效、切换音频和返回操作都清除纹理引用。
- 画面按显示宽高比 `PreserveAspectFit`，背景使用纯黑，不加边框、圆角、阴影或滤镜。
- 旋转只接受 0/90/180/270 度；异常值归一化为 0，并记录诊断。

### 5.6 QML 视频视图

在 `Main.qml` 顶层放置一个按需 `Loader`。其 active 条件为当前媒体含真实视频轨，
且播放状态不是 Stopped；它覆盖而不复制经典、单窗口和滚动主题的业务逻辑。

`VideoPlaybackView.qml` 分为：

- 上部：无边框 `VideoFrameItem`，黑色等比留边；加载和错误状态只显示短文本。
- 下部：紧凑基础控制栏，复用现有 Theme、图标、命令和控件尺度，包含上一首、
  播放/暂停、下一首、进度、当前/总时长、音量、倍速、全屏/退出全屏、返回。

所有按钮具备 Default/Hover/Pressed/Focus/Disabled 状态、键盘焦点和 tooltip。
控制栏不复制播放算法，只调用 `PlaybackController`。全屏复用主窗口并保存进入前的
窗口可见状态；`Esc` 仅退出全屏，不停止播放。返回操作先退出全屏，再 stop，并等待
视频协调层确认资源释放。应用窗口关闭仍遵循现有安全退出语义。

## 6. 数据流

### 6.1 拖放或双击

1. 现有 QML/native drop、命令行和单实例转发把本地路径交给 `ImportController`。
2. `probe_media_metadata` 识别音轨和真实视频轨。
3. `TrackRecord` 写入现有资料库/播放列表；不创建视频分类。
4. 现有导入后播放逻辑调用 `PlaybackController`。
5. 音频核心开始音轨输出或静音时间轴。
6. `VideoPlaybackController` 观察到当前记录 `hasVideo=true`，启动解码并显示顶层视图。

### 6.2 Seek、切歌与退出

- Seek 成功后视频线程 flush 并从目标附近重新解码；Seek 前 generation 的帧被拒绝。
- 上一首/下一首和自动结束继续由现有队列决定；当前 ID 改变后视频控制器关闭旧源。
- 切到纯音频时先停止/加入视频线程，再清空 CPU 帧和 Scene Graph 纹理，最后关闭
  视频 Loader。
- 返回音频播放器执行 stop；Stopped 使 Loader 隐藏。再次 play 当前视频会重新加载。

## 7. 文件关联

新增独立的 `supportedVideoExtensions()`，不改变 `supportedAudioExtensions()`，从而保证
目录扫描、音频导入对话框和音频工具仍然只面向音频。

当现有“设为默认播放器”关闭时，不写视频关联。启用时，注册音频用户选择项加固定
视频扩展名到 AgPlayer capabilities；Windows 仍由用户在默认应用界面完成最终选择。
`unregisterAll()` 同时清除音频和视频扩展，不能留下陈旧注册。

## 8. 错误与恢复

- 文件无真实视频轨：按普通音频处理。
- 视频 codec 不受随附 FFmpeg 支持：显示“无法解码视频画面”，音频若可播放则继续，
  并保留返回/切歌操作。
- 音轨存在但解码失败：沿用现有播放错误；不得悄悄改用静音时间轴。
- 无音轨且有视频轨：使用静音时间轴；无有效时长时拒绝播放并显示明确错误。
- 损坏包、Seek 失败或读取失败：停止发布新帧、记录 RuntimeLog、允许重试 Seek/切歌。
- 取消通过 FFmpeg interrupt callback 中断本地读取；测试夹具上的线程退出目标为
  500 ms，2 秒仍未退出即视为验收失败。不得分离或遗留线程来伪装关闭成功。
- Scene Graph invalidation：丢弃 GPU 资源，窗口恢复后只从最新 CPU 帧重建一次。

## 9. 性能与资源约束

- 纯音频状态下视频工作线程数为 0，帧队列为 0，视频纹理为 0，无视频专用定时器。
- 每个播放会话最多一个视频解码线程；禁止每帧创建线程或无界任务。
- 帧队列最多 3 帧/64 MiB，切歌和 Seek 清空旧队列。
- 静止画面、暂停状态和不可见窗口不持续上传相同纹理。
- 首版目标为本机 Release 下稳定播放 1080p/30 SDR 测试视频，无持续增长的内存、
  句柄或 GPU 纹理；4K、60 fps 和硬件解码不作为完成门槛。
- 视频能力不得改变纯音频的启动路径、波形缓存策略或常驻 GPU 工作。

## 10. 修改边界

预计涉及：

- 核心元数据、Decoder 选项、视频解码 C ABI 和对应核心测试；
- `TrackRecord`/`LibraryModel`/`LibraryStore`/`ImportController`；
- `VideoPlaybackController`、`VideoFrameItem`、QML 注册和 Qt 测试；
- `VideoPlaybackView.qml`、`Main.qml`、QML 测试和 CMake QML 资源；
- 文件关联控制器及设置测试；
- `docs/development/` 需求追踪与验收记录。

当前 `main` 工作树已有未提交的播放器和侧栏修改。实施必须保留这些修改，不回退、
不覆盖，也不把它们混入本功能的完成声明。对重叠的 `Main.qml`、`app/CMakeLists.txt`
和 QML 测试采用最小增量补丁，最终 diff review 明确区分既有改动和本功能改动。

## 11. 测试策略

实现遵循 RED → GREEN → REFACTOR：每一项生产行为先有能够因缺失能力而失败的测试。

### 11.1 核心自动化

- 元数据探测区分音频封面流与真实视频轨。
- 含音轨视频、无音轨视频、损坏视频和无有效时长视频。
- 静音时间轴的 duration、pause、seek、speed 和 EOS。
- 视频 C ABI open/read/PTS/seek/cancel/destroy，含旋转和非方形像素。
- 帧缓冲所有权和重复销毁安全。

### 11.2 Qt/QML 自动化

- `TrackRecord` 新字段的旧库兼容、持久化和角色。
- 直接拖放/命令行视频导入；目录扫描和音频对话框仍不发现视频。
- 当前媒体变化触发一次启动/释放；旧 generation 帧被拒绝。
- 队列上限、暂停等待、Seek flush、错误呈现和无视频零资源。
- 视频视图自动显示、切音频自动恢复、返回停止、全屏、`Esc`、控制栏动作。
- 三种主播放器 shell 共用一个顶层视频视图，没有复制业务实现。
- 文件关联只在现有默认播放器开关启用时包含视频扩展。

### 11.3 真实播放与视觉验收

- 使用可再分发的短测试媒体覆盖 H.264/AAC MP4、VP9/Opus WebM、MKV、MOV、AVI
  和无音轨 M4V；记录每个容器实际 codec、时长和结果。
- 在真实音频设备上执行播放/暂停/Seek/倍速/音量/切歌和混合音视频队列。
- 窗口模式与全屏截图，检查等比、黑边、控制栏、深/浅主题、最小窗口和 HiDPI。
- 从视频切回音频后检查线程、内存、纹理和 CPU/GPU 活动。
- 运行完整 CTest、QML lint、Release 构建、应用启动、音频格式回归和最终 diff review。

## 12. 完成门禁

只有以下条件全部满足，才能声明完成：

- 开发提示词的每项必须行为都能映射到自动化或实机证据。
- 支持矩阵中的真实文件均完成导入、画面、声音/静音时间轴、Seek 和结束验证。
- 混合音视频队列及全部播放模式没有越界或重复状态机。
- 返回、切音频、退出和 Scene Graph 失效均无遗留线程/帧/纹理。
- 纯音频路径的视频资源计数为零，且音频播放回归通过。
- Release 构建、完整测试、QML lint 和视觉验收的实际结果已记录。
- 最终 diff review 未发现无界队列、跨线程 QSG 访问、生命周期泄漏、重复控制逻辑
  或对现有未提交修改的回退。
- 未把聚焦测试、理论分析或单一格式成功冒充完整视频兼容验收。
