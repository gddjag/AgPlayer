# AgPlayer 专业十段图形均衡器设计

日期：2026-08-10
状态：已确认，待实现

## 目标与边界

在不替换现有播放器核心的前提下，为主播放器增加真实的十段图形均衡器。EQ 仅作用于主播放器实时播放，不作用于音频工具试听或导出，不调用系统全局音效，也不把 AgPlayer 扩张成 DAW。

播放器当前数据链为：

`Decoder -> PcmRingBuffer -> AudioEngine::render -> ReplayGain/音量 -> 频谱 -> 声卡`

EQ 插入点固定为 `AudioEngine::render()` 从环形缓冲读取浮点 PCM 之后、ReplayGain/音量和设备输出之前：

`PCM -> 十段EQ/前级/自动防削波 -> ReplayGain/音量 -> 频谱 -> 声卡`

## DSP 结构

新增独立核心模块 `GraphicEqualizer`，包含固定十段峰值滤波器：31.25、62.5、125、250、500、1k、2k、4k、8k、16k Hz。每段增益和前级范围均为 -12.0 至 +12.0 dB，步进 0.1 dB。

每段使用 RBJ Audio EQ Cookbook Peaking EQ 双二阶 IIR，默认 Q=1.414。系数使用 `double` 计算，PCM 处理保持现有 `float` 格式。每个声道拥有完全独立的延迟状态；实现固定容量、最多八声道，当前立体声路径使用前两个声道。

支持 44.1、48、88.2、96、192 kHz。控制线程在采样率或参数变化时重算全部系数；无效、非有限或接近 Nyquist 的频段不得进入音频线程。切歌、Seek、采样率变化和设备重建时清理滤波状态并发布匹配新采样率的参数组。

全部频段、前级和保护增益为 0 dB 时启用快速透明路径，不改变样本。所有输入和中间结果检查非有限值，输出不得产生 NaN 或 Inf。

## 实时线程模型

控制线程负责：参数校验、RBJ 系数计算、频率响应扫描、自动防削波计算、预设和持久化。音频回调只执行固定容量滤波、标量平滑和无锁命令接收；禁止锁、日志、文件访问、堆分配及容器扩容。

完整 EQ 参数以一个版本化快照提交，避免十个频段出现半更新状态。控制线程写入固定容量 SPSC 邮箱；音频线程在块边界读取并合并为最新值。

参数切换使用两套预分配滤波器组进行 25 ms 等功率交叉淡化。拖动频繁更新时保留最新待应用参数，不无限堆积。旁路使用独立的 25 ms 干湿声交叉淡化。前级和自动保护增益使用逐样本平滑。所有处理均连续，不停止或重建输出设备。

## 自动防削波

默认开启。控制线程在 20 Hz 至 `min(20 kHz, Nyquist 安全上限)` 的对数频率网格上计算十段级联幅频响应，并叠加用户前级增益。

仅当最大正增益存在削波风险时，自动增加平滑负增益，并在预测峰值下预留 0.5 dB。全零和平坦设置不额外衰减。该功能不使用硬限幅器，不修改源文件，不压缩音乐动态。

UI 显示当前自动保护增益和“保护中”状态。测试同时验证计算频响和满幅输入的峰值安全性。

## 接口与持久化

核心 C API 增加单次提交的 EQ 参数结构，包含版本、启用、旁路、自动防削波、前级、十段增益、Q 值和过渡时间。Qt 层不得逐字段直接操作音频线程。

新增 `EqualizerController` 和十段列表模型，负责：

- 参数双向同步与范围约束；
- 内置预设选择；
- 自定义预设保存、重命名、删除；
- 全部归零、启用、旁路和自动防削波；
- 实时响应曲线与保护增益；
- 将完整快照提交给 `PlaybackController`/核心 C API。

复用当前 `QSettings` 方式，在独立 `equalizer` 分组保存当前状态、最后预设和自定义预设。预设仅保存并应用同一组真实 EQ 参数，不允许另一套音效逻辑。

首批内置预设保持克制：平坦、低频增强、低频削减、人声清晰、高频增强、高频削减、摇滚。内置预设不可删除；自定义预设可保存、重命名和删除。

## 界面

播放器底部“音频工具”入口旁增加独立 EQ 线性图标。点击打开独立 `EqualizerWindow`，默认和最小尺寸均为 780x460，可拖动并向上放大，跟随现有深色、浅色和系统主题。

窗口布局沿用参考图的层次，但压缩为桌面小窗口：

- 顶部：启用、预设、保存/管理、旁路、全部归零；
- 中部：实时频率响应曲线；
- 下部：十根垂直频段滑杆和一根前级滑杆；
- 底部：自动防削波、0.5 dB 余量、保护增益和操作提示。

每根滑杆显示频率和实时 dB 值，双击归零，滚轮按 0.1 dB 调整，方向键按 0.1 dB 调整，PageUp/PageDown 按 1 dB 调整，并提供键盘焦点和无障碍名称。UI 更新通过普通 Qt 信号完成，不从音频线程直接操作 QML。

## 测试与验收

实施必须遵循测试先行。核心自动化覆盖：

- 全零时与输入近似位透明；
- 每个频段单独 +6/-6 dB，中心频率误差不超过 +/-0.3 dB；
- 44.1/48/88.2/96/192 kHz 系数和状态重建；
- 左右声道独立、无串音；
- 非法参数边界、NaN/Inf 防护；
- 25 ms 参数和旁路平滑，无突变；
- 自动防削波的级联响应与 0.5 dB 余量；
- 状态和自定义预设恢复；
- C API 参数快照的一致提交；
- QML 双向同步、双击归零、滚轮和键盘微调。

信号验证使用正弦单频、对数扫频、脉冲、满幅双声道和真实音乐。自动化输出 CSV 频响证据，记录每个采样率下十个中心频率的目标值、实测值和误差。

最终门槛为：Debug/Release 构建与全量回归通过、QML lint 无新增警告、实际声卡/耳机连续拖动滑杆、切换预设和旁路无爆音或中断。仅编译通过不算完成；无法由自动化证明的声卡听感必须明确标为待人工确认。

## 不采用的方案

- 解码线程内处理：环形缓冲中的旧 PCM 会导致参数变化延迟，不满足实时操作。
- 系统全局 EQ：不可测试、影响其他应用且违背需求。
- 通用节点式 DSP 图：当前只有单个固定 EQ，增加复杂度和体积，没有产品价值。
- 硬限幅器：会改变动态，不能替代基于响应预测的自动防削波。
