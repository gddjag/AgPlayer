# AgPlayer 格式转换完整复刻设计

## 1. 目标与验收基线

在现有 Qt 6/QML、C++17 和内嵌 FFmpeg 库上，完整实现“音频工具 > 格式转换”。页面以用户提供的 1672×942 参考图为唯一视觉基线，全部控件连接真实后端；转换不得启动外部 `ffmpeg.exe`，不得使用演示任务、假进度、假成功或静默回退参数。

参考分辨率下，四大区域的边界、间距、控件尺寸和对齐与图片逐项比对，关键边界误差不超过 2 px：

- 标题栏：高 48 px。
- 工具页签和操作工具栏：分别约 54 px、60 px。
- 主区：左侧任务区约 1216 px，右侧设置区约 445 px，中间间距 8 px。
- 底部全局控制栏：约 114 px。

高 DPI、1280×720、1920×1080 和 4K 使用同一信息结构自适应；不得缩放字体位图、遮挡控件或产生横向内容溢出。参考图中的任务属于视觉示例，产品不得写入示例数据；空队列显示真实空状态。

## 2. 范围

### 2.1 导入与任务操作

- 添加一个或多个文件。
- 添加文件夹并递归发现支持的音频文件；保留每次导入根目录。
- 从当前播放列表加入可转换文件。
- 从曲库或歌曲列表右键“使用音频工具打开”进入格式转换页并加入选中项。
- 将文件或文件夹拖到任务区导入。
- 全选、部分选择、移除选中、清空列表、失败重试和单项取消。
- 按文件名、原格式、输出格式或标签搜索；按状态与格式筛选。

### 2.2 输出格式与参数

页面固定显示八个入口，但可用状态由当前 FFmpeg 构建实时决定：

| 入口 | 容器 | 默认编码器 |
| --- | --- | --- |
| MP3 | MP3 | `libmp3lame`；不可用时按钮禁用 |
| FLAC | FLAC | `flac` |
| WAV | RIFF/WAVE | 用户确认的 PCM 编码 |
| AAC | ADTS | `aac` |
| Opus | Ogg | `libopus` 或明确展示的可用 Opus 编码器 |
| OGG | Ogg | Vorbis 编码器 |
| ALAC | M4A/MP4 | `alac` |
| M4A | M4A/MP4 | `aac` |

格式可用必须同时满足编码器、复用器和组合兼容性。禁用按钮显示具体原因，不得在点击后才失败，也不得改用未展示的编码器或容器。

参数区根据所选格式动态展示：编码器、CBR/VBR 或质量模式、目标码率/质量、采样率、声道布局、位深或采样格式，以及格式专属选项。所有候选值来自编码器能力枚举或实际打开编码器的预检。`自动`优先保持源参数，但启动前必须展示每个任务的最终解析结果。

### 2.3 输出选项

- 输出目录及目录选择器。
- 文件冲突策略：自动序号、跳过、覆盖、询问。
- 保留元数据。
- 保留封面。
- 保留文件夹导入的相对目录结构。
- 从视频文件中提取音频。

以上选项均必须真实生效。关闭视频提取时，视频输入在预检阶段拒绝；开启后默认选择带 `default` 标记的最佳音频流，多音轨且选择有歧义时必须让用户在任务详情中选择。普通视频流不得写入音频结果，封面流只在目标容器支持且预检计划确认时保留。

## 3. 界面设计

### 3.1 顶部区域

保持参考图中的四个工具页签和“格式转换”蓝色选中态。操作工具栏从左到右为：添加文件、添加文件夹、从播放列表添加、移除选中、清空列表；右侧为搜索框和筛选按钮。按钮使用现有图标组件与颜色令牌，不使用字符冒充图标。

### 3.2 任务区

任务区使用 `QAbstractTableModel`、筛选代理模型和 QML `TableView`，不能继续通过完整 `QVariantList` 重建全部行。列顺序严格为：勾选、文件名、原格式、时长、采样率、码率、输出格式、状态、进度。1000 项任务滚动、搜索和状态刷新时保持响应。

顶部状态标签为：全部、转换中、已完成、失败、已取消，并显示真实数量。列表行选择与任务勾选相互独立。状态文字和颜色来自任务状态机；进度条来自实际处理阶段。任务底部显示真实总数和勾选数。

任务状态为：分析中、就绪、待确认、排队中、转换中、校验中、提交中、已完成、失败、已取消。失败行可打开详情、复制诊断并重试；取消任务不得变成失败。

### 3.3 设置区

右侧保持参考图的 A/B/C 三段结构：

- A. 输出格式：两行四列格式按钮，当前格式蓝色高亮；不支持项禁用并有原因提示。
- B. 编码参数：控件随能力目录变化；不可用的固定值不显示为可点击项。
- C. 输出选项：输出目录、冲突策略和四个真实复选项；底部提示说明本地处理及平台编码能力差异。

设置区内容超出高度时仅内部滚动，不改变任务区和底栏的固定结构。

### 3.4 底部控制栏

底栏实时显示时长加权总进度、任务数、ETA、并发数、输出目录、完成数和失败数。并发数至少支持 1、2、4，并受合理上限约束。“开始处理”先执行全部勾选任务的预检；“取消全部”只取消正在运行或排队的任务。

## 4. 架构与模块边界

采用“保留核心、重建契约”的方案，不整体重写播放器或转换器：

1. **转换能力目录**：枚举编码器、复用器、采样格式、采样率、声道布局和可用 AVOption，提供不可用原因。
2. **转换计划与预检器**：把 UI 请求冻结为不可变批次计划，解析每项实际参数、音轨、元数据/封面策略和目标路径，并生成“请求值 → 实际值”差异。
3. **任务表格模型**：以稳定任务 ID 保存源信息、导入根目录、勾选状态、阶段、进度、解析结果、目标路径和诊断；通过细粒度模型信号更新行。
4. **队列调度器**：使用受控线程池执行独立任务，控制并发、取消、状态合法转换和播放器共存。
5. **FFmpeg 转码核心**：继续使用 `core/src/transcoder.*` 的直接库 API，补齐能力、音轨、元数据/封面和管线正确性，不启动子进程。
6. **验证与提交器**：关闭临时输出后重新打开并完整解码，校验结构、时长、样本数及计划中的元数据/封面，最后原子提交。
7. **QML 页面**：只负责布局、用户输入、筛选、选择、预检确认和诊断展示，不进行文件扫描、参数猜测或转换业务。

`FormatConverter` 保持 QML 门面职责，公开任务模型、筛选模型、能力目录、当前设置、预检摘要和队列操作。职责较大的实现拆入专用类，避免继续扩大单一控制器。

## 5. 数据流

1. 用户从文件、文件夹、播放列表、右键入口或拖放导入。
2. 后台探测输入，模型逐项填充容器、音频流、时长、码率、采样率、采样格式、声道布局、标签和封面信息。
3. 用户勾选任务并设置格式、编码参数和输出选项。
4. “开始处理”冻结批次，预检所有勾选任务；统一预留输出路径，避免并发抢占同名目标。
5. 如存在参数差异、冲突询问、不可保留项或多音轨歧义，进入待确认并展示逐项摘要；用户确认前不运行。
6. 调度器按并发限制执行：Demux → Decode → Swr → `AVAudioFifo` → Encode → Mux → Trailer → 刷盘。
7. 同目录临时文件关闭后重新打开，完整解码验证；验证通过后原子改名或替换。
8. 模型更新最终状态、进度、计数、ETA 和诊断。

## 6. 转换正确性与输出安全

必须正确处理解码与编码的 `send/receive`、`EAGAIN`、EOF 和刷新；排空 Swr 尾样本与 FIFO，覆盖固定帧长、可变帧长和不足尾帧；使用真实帧参数处理 planar/interleaved、采样格式、采样率和声道布局转换。所有 packet 在写入前正确换算时间基，输出音频时间线归一化且连续。

临时文件与最终文件位于同目录、同卷；取消或失败清理临时文件。覆盖策略不得直接写坏旧文件：只有 trailer、刷盘、完整校验全部成功后才原子替换。自动序号在启动前统一预留；保留目录结构只允许位于输出根目录内，拒绝路径穿越。

Windows 路径使用 Unicode 安全转换。输入和输出同源判断只有在路径规范化成功时才比较，不能把两个规范化失败的路径误判相同；不存在的待创建输出使用适合的弱规范化策略。

进度在转换、校验、提交全部完成后才允许达到 100%。总进度按任务有效时长或已知工作量加权，并对未知时长任务使用明确的保守权重。

## 7. 错误与取消

每个失败诊断包含任务 ID、输入路径、临时输出路径、阶段、FFmpeg 错误码和文本、请求参数、实际参数、最近时间戳或样本数、是否可重试和清理结果。UI 默认显示简洁原因，详情可复制完整诊断。

阶段至少覆盖：探测、预检、打开输入、打开解码器、初始化 Swr、打开编码器、写 Header、Demux、Decode、Resample、FIFO、Encode、Mux、Flush、Trailer、刷盘、完整校验、原子提交。错误不得被统一替换为“转换失败”。

取消令牌贯穿 FFmpeg interrupt callback 和热循环。取消排队任务立即生效；取消运行任务安全停止、释放资源并清理临时文件；已验证提交的结果不回滚。

## 8. 测试与视觉验收

严格先写失败测试再实现，测试音频由程序生成，不使用受版权保护的媒体。

### 8.1 模型与预检

- 能力枚举同时检查编码器和复用器，并验证禁用原因。
- 请求参数与实际参数差异、禁止静默修改、未消费 AVOption 报错。
- 合法状态转换、勾选与行选择独立、搜索筛选、计数和时长加权进度。
- 自动序号并发预留、跳过、覆盖、询问、同源拒绝和目录穿越拒绝。
- Unicode 中文路径、长路径、只读源文件和不存在的输出路径。

### 8.2 FFmpeg 与格式矩阵

- `send_packet/receive_frame`、`send_frame/receive_packet` 的正常、`EAGAIN`、EOF 和刷新。
- Swr 尾样本、FIFO、固定/可变帧长、小尾帧、44.1/48/96 kHz、mono/stereo/5.1、16/24-bit/float。
- 当前构建实际可用时验证：WAV → MP3/FLAC/AAC/M4A/Opus/OGG/ALAC、FLAC → MP3、MP3 → FLAC。
- 视频多音轨选择、元数据保留、封面保留及不可保留时的确认门。
- 每个结果重新打开并完整解码；无损结果验证有效 PCM，有损结果验证结构、完整解码和有效时长。
- 取消、损坏输入、写盘失败、trailer 失败和原子提交失败不得产生伪成功或破坏旧文件。

### 8.3 UI 与性能

- QML 契约测试覆盖全部控件、状态筛选、动态禁用、预检确认、错误详情和底栏指标。
- 以 1672×942 截图与参考图对比，关键边界误差不超过 2 px；人工检查颜色、字体、图标、圆角、间距、列宽和各状态。
- 验证 1280×720、1920×1080、4K 和 Windows 缩放场景。
- 验证 1000 条任务的滚动、筛选和进度更新；转换时切换工具页、缩放窗口和播放音频保持响应。

## 9. 完成定义

只有同时满足以下条件才能报告完成：

1. 参考图四区结构和全部控件通过视觉对比，且其他目标分辨率无溢出。
2. 截图和本文列出的每个控件均有真实后端效果，没有禁用占位或演示数据。
3. 单文件、批量、文件夹、播放列表、右键和拖放导入真实可用。
4. 八个格式入口按当前 FFmpeg 实际能力启用或明确禁用；所有参数经过预检且无静默修改。
5. 元数据、封面、目录结构、视频音轨和四种冲突策略按确认计划执行。
6. 任务进度、状态、计数和错误诊断来自真实管线；校验和提交前不显示 100%。
7. 格式矩阵、中文路径、完整解码验证、取消清理和旧文件保护测试通过。
8. 相关单元、集成、QML 和完整构建通过，零新增编译警告。
9. 真实本地文件转换后由应用重新打开验证；报告样本、参数、输出和测试结果。
10. 不覆盖其他未提交改动，不自动打包或替换已安装程序；打包必须由用户另行明确要求。

## 10. 非目标与变更边界

本轮不加入响度标准化、联网标签、CD 抓轨、剪辑、AI 处理或其他工具页重构。只修改格式转换 QML、Qt 模型/门面、必要的 FFmpeg 转换与能力边界、对应测试、翻译和设计/实施文档；共享文件仅做最小注册或构建调整。

实现为 clean-room 原创，仅使用现有 Qt 和 FFmpeg 依赖，不阅读或复制 fre:ac 的源码、二进制或内部结构。工作树中的既有修改均保留。
