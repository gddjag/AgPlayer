# AgPlayer 格式转换整改设计

## 目标

在既有 Qt 6/QML + C++17 + FFmpeg 库内转换链路上，完成与用户参考图同构、全部控件真实可用的“音频工具 > 格式转换”页面。不得调用 `ffmpeg.exe`、不得伪造状态或进度、不得影响其他音频工具。

## 范围

- 顶栏：添加文件、添加文件夹、从播放列表添加、移除选中、清空、按文件名/格式/标签搜索、状态筛选。
- 任务区：虚拟化表格；独立的行勾选与行焦点；全部、转换中、已完成、失败、已取消筛选；真实源信息、输出格式、状态、进度与错误操作。
- 右侧：MP3、FLAC、WAV、AAC、Opus、OGG、ALAC、M4A 格式入口；实际 FFmpeg 能力决定可用状态与原因。动态展示编码器、码率模式、目标码率/质量、采样率、声道、采样格式及格式专属项。
- 输出：输出目录、自动序号/跳过/覆盖/询问冲突策略、保留元数据、封面、导入根目录的相对目录结构、视频提取音频。
- 底栏：时长加权总进度、ETA、并发数、输出目录、完成/失败数量、启动与取消全部。

不包含响度标准化新功能、联网标签、剪辑、CD 或任何其他工具页整改。

## 架构

保留 `core/src/transcoder.*` 作为同步的 FFmpeg 转码链路，保留 `FormatConverter` 作为 Qt 队列适配器；只扩展其公开的、可测试的转换计划、能力信息和任务视图数据。QML 只进行布局、选择与显示，所有文件扫描、预检、转码、校验、提交均在 C++ 后台线程完成。

`FormatConverter` 在启动前把所选任务和 UI 设置冻结为不可变计划：解析格式/容器/编码器及参数；对每个输入生成真实解析值与差异；预留输出路径；检测同源同目标、视频规则、保留元数据/封面兼容性。存在差异或需要用户决定的冲突时进入“待确认”，不运行任务。确认后按受控线程池运行。

转换继续沿用现有 FFmpeg 库 API 和取消令牌。每项任务依次经过转换、重新打开验证、原子提交；验证和提交未完成前不可达 100%。失败和取消删除同目录临时文件；覆盖仅在验证通过后原子替换原文件。

## 数据与交互

任务数据增加稳定任务 ID、导入根目录、是否勾选、阶段、已解析输出参数、错误详情、预计工作量与运行快照。状态采用：分析中、就绪、待确认、排队中、转换中、校验中、提交中、已完成、失败、已取消。QML 表格按该模型直接呈现；选择任务不等同于勾选任务。

格式能力由当前 FFmpeg 的编码器和复用器枚举得出。若目标不可用，按钮禁用并显示原因；不回退替代编码器或容器。参数值由能力查询和开编码器预检共同确认；未消费 AVOption 与不兼容组合均为明确错误。

视频默认选择 default 标记的最佳音频流；多音轨时任务详情要求选择。保留封面/元数据无法由目标表达时，预检列出丢失项并请求确认。

冲突策略：自动序号在批次启动前统一预留；跳过标记任务跳过；覆盖在安全提交时替换；询问形成待确认项。目录结构仅按文件夹导入根目录求相对路径，并拒绝路径穿越。

## 测试与验收

先加失败测试，再实现。覆盖：能力禁用与原因、计划差异/确认门、冲突策略与并发预留、勾选批处理、阶段进度、取消清理、同源拒绝、真实格式矩阵及重新打开验证。补 QML 契约测试：截图四区布局、控件对象名、状态筛选、搜索、动态格式禁用、底栏指标。用项目既有 MSVC x64 构建预设运行相关 CTest 和真实生成 WAV 的转换测试；不自动打包。

## 风险控制

工作树已有大量未提交改动。本次只改格式转换的 QML、Qt 适配器、必要的转换/能力边界、相关测试、翻译与该规格；共享文件仅作最小注册或构建调整。保留既有临时文件、重新打开验证和原子提交路径，避免破坏正在运行的播放器。

## 完成定义

参考图四区结构和文本可用；截图中的每个格式转换控件都有真实后端效果；格式/参数仅来自实际 FFmpeg 能力；开始前不能静默改参数；完成状态只在验证与原子提交成功后出现；相关自动化测试、构建和真实转换验收均有输出证据。
