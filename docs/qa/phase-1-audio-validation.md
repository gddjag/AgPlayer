## Seek Latency

Command: `seek_benchmark.exe tests/fixtures/generated/sample.flac`

Release build:

```json
{
  "device": "null",
  "backend": "AG_AUDIO_BACKEND_NULL",
  "file": "sample.flac",
  "samples": 100,
  "min_ms": 0.3292,
  "median_ms": 30.7295,
  "p95_ms": 31.7431,
  "max_ms": 32.3957,
  "passed": false
}
```

- **P95 threshold:** < 20ms
- **P95 measured:** 31.74ms (Release), 31.85ms (Debug)
- **Result:** FAIL — P95 exceeds 20ms threshold

**Analysis:** The min seek latency is 0.33ms, confirming FFmpeg's `av_seek_frame` is fast. The ~30ms median is dominated by `AudioEngine::seek()` thread management overhead: each seek stops the output device, stops the decode thread, restores the decoder, seeks, clears the ring buffer, restarts the decode thread, and restarts the output device. This architecture guarantees correctness but adds ~30ms of thread lifecycle overhead per seek. Meeting P95 < 20ms would require optimizing the seek path (e.g., pausing rather than stopping threads, or seeking without full thread restart).

## Memory

Command: `tools/memory_probe.ps1 -Executable <AgPlayer.exe> -AudioFile <sample.flac>`

Release build:

```json
{
    "StableWorkingSetMB":  83.25,
    "LimitMB":  60,
    "Passed":  false
}
```

- **Stable working set threshold:** < 60MB
- **Stable working set measured:** 83.25 MB (Release), 122.07 MB (Debug)
- **Result:** FAIL — exceeds 60MB threshold

**Analysis:** The working set includes Qt6 DLLs (~30-40 MB), FFmpeg DLLs (~10-15 MB), QML engine and loaded components (~10-15 MB), and the audio engine with ring buffer and decoder (~5-10 MB). The 60MB threshold is aggressive for a Qt6/QML desktop application. Optimizing memory to < 60MB would require lazy-loading Qt modules, reducing the ring buffer size, or moving to a lighter UI framework.

### Concerns

1. **Seek P95 (31.74ms vs < 20ms):** The seek path stops and restarts the decode thread and output device per seek, adding ~30ms overhead. Optimization is needed to meet the 20ms threshold.
2. **Stable working set (83.25 MB vs < 60MB):** Qt6/QML + FFmpeg runtime accounts for most of the working set. The 60MB threshold may need revision for a Qt6 desktop app, or memory optimization is needed.
3. **queue_gapless_test Release timeout:** The test uses `assert()` for control flow validation, which is a no-op under `NDEBUG`. The test passes in Debug mode, confirming Gapless functionality. The test should be refactored to use explicit checks instead of `assert()`.
4. **Real-device playback:** Manual interactive checks are pending; automated gates used the null audio backend.

*Gapless result is based on Debug-mode ctest; Release-mode timeout is a test design issue, not a functionality issue.
