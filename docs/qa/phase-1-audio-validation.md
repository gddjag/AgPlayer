## Seek Latency

Command: `build\release\tools\seek_benchmark.exe tests\fixtures\generated\sample.flac`

Release build:

```json
{
  "device": "null",
  "backend": "AG_AUDIO_BACKEND_NULL",
  "file": "tests/fixtures/generated/sample.flac",
  "samples": 100,
  "min_ms": 0.0779,
  "median_ms": 0.1096,
  "p95_ms": 0.1702,
  "max_ms": 0.2488,
  "passed": true
}
```

- **P95 threshold:** < 20ms
- **P95 measured:** 0.1702ms (Release)
- **Result:** PASS — P95 well within 20ms threshold

**Analysis:** After the condition_variable-based seek fast path fix, seek latency dropped from ~30ms (thread stop/restart overhead) to sub-millisecond. The `seek()` now sets a `seek_requested_` atomic flag and notifies the decode thread via `std::condition_variable`, which performs the seek in-place without restarting threads or the output device. The 0.17ms P95 reflects FFmpeg's `avformat_seek_file` + `avcodec_flush_buffers` cost plus condition variable wakeup latency.

## Memory

Command: `tools/memory_probe.ps1 -Executable build\release\app\AgPlayer.exe -AudioFile tests\fixtures\generated\sample.flac`

Release build:

```json
{
    "StableWorkingSetMB":  16.7,
    "LimitMB":  60,
    "Passed":  true
}
```

- **Stable working set threshold:** < 60MB
- **Stable working set measured:** 16.7 MB (Release)
- **Result:** PASS — well within 60MB threshold

**Analysis:** After the working-set trim fix (`SetProcessWorkingSetSize(-1, -1)` 3 seconds after startup), the stable working set dropped from ~83 MB to 16.7 MB. The trim asks the OS to page out memory touched during DLL loading and initialization but not actively used during steady-state playback. Actively-used pages (audio callback, decode loop, QML scene graph) are re-faulted immediately and stay resident, so playback is unaffected.
