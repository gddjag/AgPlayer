# AgPlayer Windows / macOS 六轨音频编辑复刻说明

适用对象：接手 AgPlayer PC 版音频编辑开发的 Codex。依据：2026-09-15 当前 `codex/HarmonyOS` 工作区源码，以及同仓库 Qt/QML PC 编辑器。工作区包含未提交修改，实施时先确认实际源码基线。

**目标：将鸿蒙版的六轨、片段式、非破坏编辑操作迁移到 Windows / macOS；PC 编辑器右侧已有的升降调、速度/BPM、共振峰保护面板保持原来的位置、控件、参数含义和处理效果。**

这份文档区分三件事：鸿蒙目前已经实现的行为、PC 鼠标/键盘适配要求、PC 原有能力的保留要求。它不是“PC 已经完成六轨”的验收报告，也不把尚未完成的真机检查写成已通过。

## 1. 给 Codex 的任务范围

1. 在现有 Qt/QML 音频编辑页中完成六轨改造，沿用现有 C++ 音频核心、解码器、播放器输出、波形管线和主题。
2. Windows 与 macOS 共用编辑模型和混音处理；文件选择、麦克风、快捷键和系统窗口交互使用各平台已有适配。
3. 保留 PC 右侧参数区和已有导出能力。不要把鸿蒙 ArkUI 页面、OHAudio 或移动端录音 API 直接复制到 PC。
4. 不新建第二个播放器、第二套独立波形分析系统，不引入网页运行时或 AI 模型来实现编辑。
5. 本次是六轨音频编辑改造；播放器主界面、音乐库、伴奏分离等其他工具不在重设计范围内。

- 编辑区域占主要空间；右侧 PC 参数面板保持原布局，不改成手机折叠页。
- 六条轨道固定高度，不为了全屏同时塞下六轨而压扁波形；空间不足时上下滚动。
- 缩放只改变时间轴长度，不改变轨道高度；缩放和平移对所有轨道使用同一个时间窗口。
- 不在波形上叠文件名、粗边框、按钮阵列或大块选区文字；名称与控制集中在左侧轨头。
- 页面与图标遵循现有桌面主题；macOS 保留原生窗口/菜单/Command 快捷键习惯，Windows 使用相应桌面习惯。

## 3. 工具栏和图标顺序

| 位置 | 功能 | 图标/显示 | 实际动作 |
|---|---|---|---|
| 第一排 1 | 添加文件 | 加号＋文字 | 一次添加多个音频或有音轨的视频 |
| 第一排 2 | 回到头部 | 常规“到最前端”图标，不显示文字 | 定位到 0；原来播放则继续播放，原来暂停则保持暂停 |
| 第一排 3 | 播放/暂停 | 三角/双竖线，不显示文字 | 播放或暂停所有未静音轨道 |
| 第一排 4 | 录音 | 红色圆点＋文字 | 向当前选定轨道录音；录制时变红色停止方块 |
| 第二排 1 | 撤销 | 撤销箭头＋文字 | 恢复上一次编辑状态 |
| 第二排 2 | 分割 | 剪刀＋文字 | 在游标处切开选中片段 |
| 第二排 3 | 删除 | 垃圾桶＋文字 | 删除选中片段，保留空白 |
| 第二排 4 | 导出 | 导出图标＋文字 | 导出整条工程时间线的混音 |

按钮框、图标尺寸、文字基线、间距一致；不能用拉伸图标或字符符号代替。录音红色使用 `#FF4D5E`。PC 优先使用现有图标资源库；图标含义与排列对齐鸿蒙，不要求使用鸿蒙系统符号文件。

**“回到头部”不是暂停时自动开播。** 鸿蒙当前代码为 `seek(0)`，避免把无障碍名称“从头播放”误当成另一种行为。

## 4. 六轨模型和轨头

| 轨道 | 对齐色 |
|---|---|
| 1 | 紫 `#BD91FF` |
| 2 | 青 `#5CDDE2` |
| 3 | 粉 `#FF9EBC` |
| 4 | 金 `#F7CF73` |
| 5 | 绿 `#78D7A3` |
| 6 | 蓝 `#8FACFF` |

- 鸿蒙轨道高 86 vp、标尺高 26 vp；PC 采用约 86 个逻辑像素作为初始密度，允许随桌面字号/DPI适配，不能当作物理像素硬编码。
- 轨头与波形行严格对齐。轨头第一行显示文件名，过长省略；选中片段时显示该片段源文件名，否则显示本轨第一片段名；空轨显示“轨道 N”。
- 轨头显示轨道编号、M 静音、整体音量数值和滑杆。
- 轨道整体音量默认 100%，范围 0–200%，步进 1%。M 不删除片段，取消静音后恢复该轨原有音量。
- 选中轨道主要高亮轨头/编号；选中片段只铺对应轨道色约 7% 的淡底，不增加粗框。
- 普通波形保持清晰；静音轨波形降为约 30% 不透明度。
- 每轨可有多个片段。同轨禁止重叠；不同轨可以在同一时间发声。

### 片段必须保留的字段

```text
Track: id / name / color / muted / gain / clips
Clip:  id / sourceId / trackId / timelineStart / sourceStart / duration / envelope
Source: 原文件身份和读取入口 / 媒体信息 / 可复用波形数据
GainPoint: 片段内时间 / gain
```

时间线起点和原文件读取起点必须分开。移动片段只改时间线位置；分割修改片段范围；两者都不改写原文件。

## 5. 添加文件和自动分配

1. 无需先点击轨道，添加按钮始终能够打开多选文件选择器。
2. 一次选择 3–6 个文件时，分别放入不同轨道，起点统一使用导入开始时的游标位置。
3. 优先空轨；没有空轨时，选择该时间段没有片段冲突的轨道。本批已分配的轨道不再分配第二个文件。
4. 不能把多个文件全部塞进当前轨、静默覆盖原片段，或擅自把后面的文件拼到工程尾部。
5. 每个文件单独验证。读取失败、没有可解码音轨、无有效时长、超过限制、没有可用轨道空间，要显示对应文件及原因。
6. 某个文件失败继续其余文件；失败文件不占用轨道名额。取消保留已成功导入的文件。
7. 支持音频，以及可由当前解码器读取音轨的视频。鸿蒙选择器目前包括 MP3/WAV/FLAC/M4A/AAC/AIFF/OPUS/OGG/MP4/MOV；PC 原来支持的格式不能因此减少。扩展名匹配不等于保证解码成功。

PC 适配：系统多选对话框与文件拖入共用同一导入逻辑。拖入编辑区域的多个文件默认自动分轨；不要用不同入口产生不同的覆盖/排序规则。

## 6. 时间轴和波形显示

- 空工程显示 30 秒窗口；有内容后视图边界限制到最后一个片段结束。
- 不允许滚动到工程尾部之后无意义的大段空白；工程内部由片段移动产生的真实空隙要保留。
- 放大以鼠标/双指中心对应的时间为锚，放大后该位置不应突然跳走。
- 标尺与六轨一起缩放，刻度自动切换；小范围显示小数秒，不堆叠互相覆盖的数字。
- 鸿蒙最小可视范围约 100 ms，刻度目标间隔约 72 vp。PC 初版可沿用，再按实际可读性适配。
- 画连续上下对称的峰值包络，不改成等距竖条频谱。
- 每个屏幕像素覆盖的音频区间取峰值，保留瞬态；不能靠放大低分辨率图片冒充细节。
- 快速缩放先用已有缓存；手势停止后补取当前可见区的高精度数据。鸿蒙当前细节请求延后约 250 ms、最多缓存 24 段，5 分钟以上的视窗不请求细节。
- 波形底层、音量线、游标分层。播放只更新游标，不每帧重新解码或重画全部波形。
- 波形缓存按音源和源时间区间复用；移动片段、改变轨道色、静音和改变音量，不应重新分析整首源文件。

**“放大保留细节”是使用源数据按需补充，不是无限放大仍声称拥有不存在的采样精度。**

## 7. PC 手势与键鼠映射

| 操作 | 鸿蒙当前方式 | PC 要求 |
|---|---|---|
| 选片段/定位 | 轻点片段 | 单击波形片段，选片段并定位 |
| 空白定位 | 轻点空白 | 单击轨道空白，选择轨道、清除片段选择并定位 |
| 拖游标 | 按标尺或游标附近拖动 | 按住标尺/游标拖动；命中区大于可见线宽 |
| 时间缩放 | 双指横向缩放 | 触控板捏合；Ctrl/Command＋滚轮缩放，鼠标指向处为锚 |
| 水平平移 | 快速横向滑动 | 水平滚轮/触控板横移、Shift＋滚轮或水平滚动条 |
| 上下看轨道 | 快速纵向滑动 | 普通滚轮/触控板纵移或纵向滚动条 |
| 移动片段 | 长按约 300 ms 后拖动 | 鼠标按下后越过拖动阈值直接拖；触屏继续支持长按 |
| 跨轨移动 | 长按片段后上下拖动 | 拖至目标轨，左右位置仍由统一时间线计算 |
| 添加音量点 | 双击细音量线 | 双击音量线，不与片段拖动争抢 |
| 调音量点 | 拖动已有点 | 抓点拖动；可见点小，命中范围适当扩大 |
| 取消当前手势 | 系统取消事件 | Esc/失去指针捕获，恢复拖前状态 |

PC 快捷键优先使用现有绑定；新增常用绑定可采用空格播放暂停、Home 回头、标准撤销键、Delete/Backspace 删除。保留原有分割快捷键，避免冲突。输入框编辑时不得把空格、删除或快捷键误当作时间线命令。

拖片段接近视口边缘自动滚动是合理的 PC 适配增强，当前鸿蒙尚没有该能力；若实现，不能改动碰撞和松手提交规则。

## 8. 播放、拖游标和异步状态

### 核心规则

1. 一条统一的工程播放时间，全部未静音轨道同步。
2. 点击播放直接开始准备当前播放点所需的短缓冲；禁止先导出整首 WAV 再播放。
3. 波形细节分析不能阻塞播放或定位；导入概览和后台补细节分开。
4. 拖游标开始时记录“拖前是否播放”，暂停音频。
5. 未松手只更新视觉游标和时间，不为每个移动事件调用解码、seek 或完整混音。
6. 松手仅提交最终位置。拖前播放则在该点续播；拖前暂停则保持暂停。
7. 取消手势恢复拖前位置和播放状态；第二指进入缩放时不能误提交定位。
8. 连续点定位/快速操作只保留一个正在执行的 seek 和最新目标，不能堆积过期请求。
9. 给编辑、定位和预览准备附加修订号；旧异步结果不得覆盖更新后的工程或游标。
10. 显示进度以实际音频播放位置为依据，可在相邻确认值间平滑插值，不用假计时器假装音频已经播放。

当前鸿蒙编辑动作会先暂停再提交，未承诺修改片段、音量或静音后无缝保持播放。PC 可以保持已有实时调参能力，但不得为追求动效牺牲音画同步。

## 9. 片段拖动、吸附和跨轨

- 保留按下时抓取点与片段左边缘的距离；不能一拖动就让片段头突然对齐鼠标。
- 拖动阶段只显示预览位置；松手提交一次编辑。提交期间保留目标位置图像，不能先弹回原位置。
- 片段头/尾接近其他片段头/尾、时间 0 时吸附。鸿蒙阈值为当前缩放下约 8 vp 的时间距离；PC 对应约 8 个逻辑像素，而非固定多少毫秒。
- 不同轨道片段边缘也可作为吸附参考，便于节拍/段落对齐。
- 同轨碰撞时寻找邻近合法空隙；没有可放位置则说明原因并保留原片段。禁止重叠覆盖、自动推开其他片段或把拖放失败表现成无解释的回弹。
- 跨轨移动同时改变轨道归属和时间线位置，保留原音源区间、时长、音量控制点。
- 跨轨后波形使用目标轨颜色，声音使用目标轨音量和静音状态。
- 一次完整拖放只产生一个撤销步骤，能同时恢复原轨道和原位置。

## 10. 分割、删除、撤销

- 分割对象是当前选中片段，切点必须在片段内部；不能仅靠游标所在轨猜测要切哪个片段。
- 分割后右片段被选中，左右两片引用同一音源；右片源起点相应增加。
- 音量包络在切点插值，两片边界音量连续；右片控制点改成相对右片的新时间。
- 删除仅删除选中片段，后方片段位置不动，留下空白；这不是波纹删除。
- 删除不会删除磁盘源文件。
- 撤销覆盖导入、分割、删除、移动/跨轨、静音、轨道音量、音量点等模型变更。
- 鸿蒙当前保留 40 个撤销检查点，没有重做；PC 原有重做/历史能力保留，不为对齐手机而删除。
- 当前鸿蒙没有拖片段左右边缘裁剪手柄。主要流程是“定位→分割→删除→移动”；PC 已有裁剪能力可保留，但不能冒称它是鸿蒙本次新实现。

## 11. 音量线和控制点

- 每片段有独立音量包络，初始首尾均为 100%；线在波形中央。
- 普通线宽约 1 个逻辑像素，不透明度约 35%；选中点半径约 2.5，未选中约 1.8。细而可操作，不盖住波形。
- 双击线附近新增控制点；拖点横向改时间、纵向改音量。
- 增益范围 0–200%；点按时间排序，相同时间替换；最多 128 点/片段。
- 相邻控制点间线性插值，边界之外沿用边界增益。
- 实际片段增益 = 轨道整体增益 × 片段包络增益；静音时为 0。
- 混音预览和导出必须使用同一个包络求值实现，不能只让曲线看起来在变。
- 当前鸿蒙没有专用的单点删除交互；PC 可保留已有对应操作，新增操作需明确写进验收，不凭界面样子推断存在。

## 12. 录音

- 录音到当前选择的轨道，从当前游标开始。必须明确显示目标轨道和输入设备。
- 当前鸿蒙会先暂停混音再录音，允许在空轨或本轨最后片段之后开始；不在中间空隙无限录到覆盖其他片段。
- 红圆开始，红方块停止；录制时显示真实时长，停止后生成波形并加入同一轨道/起点。
- 系统麦克风授权、权限失败、设备拔出、录音初始化失败必须有真实提示并可恢复。
- 显示内置/USB/有线/蓝牙输入及当前实际路由。鸿蒙目前监听系统路由，不能描述成已经实现强制选择任何外置麦克风。
- PC 使用现有音频输入设备枚举和录音后端，不复制鸿蒙 AVRecorder。原有输入选择能力应保留。
- 鸿蒙当前录音为 AAC/M4A、48 kHz、单声道、192 kbps；PC 原有更高品质录制设置保留，不强制降到移动端编码。
- 当前没有“边播放伴奏边录新轨”、低延迟输入监听、多路同时录音或录制中实时波形。这些不是本轮复刻的已完成功能，不要用假波形/假监听补齐。

## 13. PC 右侧升降调 / BPM / 共振峰保护：必须保留

**现有 PC 右侧参数属于整个编辑会话，不是每轨各一份。六轨改造后继续采用工程/总线作用域，不能随着点击片段偷偷变成逐轨参数。** 鸿蒙六轨页本身没有这个右侧面板。

- 保持控件位置、排列、范围、默认值、原始/目标 BPM 联动、重置和预览/导出语义。
- 当前 PC 数值：速度 0.50–2.00 倍，步进 0.01；原始/目标 BPM 为 20–400 的整数；升降调 −12～+12 半音，步进 1。C++ 的音分能力不等于本轮要新增音分控件。
- 已知原始 BPM 时，速度倍率＝目标 BPM÷原始 BPM；原始 BPM 未知时第一次输入同时成为原始 BPM，速度保持 1 倍。保持音调与共振峰保护是两个独立开关，均保留。
- 六轨先按各轨静音、音量和包络混音，再进入同一份现有 TimePitch 处理链，统一作用于整项编辑输出。
- 不能对每轨应用一遍工程变速，混音后再重复应用；BPM 换算与速度也不能叠加两次。
- 时间线继续使用工程时间，实际输出长度随工程速度变化。游标、seek、选择范围、导出范围统一沿用并扩展当前 PC 的坐标换算，不能混用源文件时间、工程时间和变速后输出时间。
- PC 已有 Signalsmith 优先、SoundTouch 回退的引擎选择，不能因为鸿蒙封装采用 SoundTouch 就切换 PC 默认引擎。
- 共振峰保护继续使用真实后端实现和原有可用性判断；不做仅改变按钮外观的假开关。
- PC 当前“重置”会恢复速度 100%、升降调 0、保持音高开启、共振峰保护关闭，并保留已知原始 BPM。继续保留此语义，不把它重新解释成“只重置 BPM”。
- 预览与导出使用同一份参数快照、同一后端处理能力；保存音频不能漏掉共振峰保护或以不同速度导出。
- 播放中改参数时，保留真实工程游标位置，重备新参数流后从该处续播；暂停中修改则在下次播放时生效。不能每调一次参数就把工程从头播放。

## 14. 实现方法与复用边界

### PC 不能只增加六行 UI

当前 PC `AudioEvent` 没有轨道归属；`EventTimeline` 对事件采用整体不重叠约束。必须补轨道归属、改为每轨碰撞判断，并增加真正的并行轨道混音，才能得到六轨编辑。

保留现有编辑 Controller 与公共 Core 的职责边界，在必要位置扩展数据和命令，不同时造一套完全独立的 PC 编辑器状态。

### 预览链

```text
工程片段快照
  → 按当前时间查找各轨有效片段
  → 现有 FFmpeg/Decoder 按需读取源区间
  → 统一 PCM / 应用轨道增益和片段包络
  → 多轨相加及现有防削波策略
  → PC 会话级 TimePitch（保留右侧参数）
  → 现有音频缓冲和平台输出
```

原生解码/混音线程拥有相关 Decoder；打开、读取、seek、关闭不能跨线程并发操作同一实例。取消先通知工作线程，退出后释放资源；音频实时回调不做文件 I/O、整首分析、长锁或大块内存分配。

鸿蒙参考 `TimelineStream` 按需打开解码器，每次最多读取 1024 帧 48 kHz 双声道 PCM，并复用已打开的时间线；这是低等待预览的参考实现。PC 的设备输出规格和现有重采样策略保留，不把该移动端规格当作全部输入的文件规格。

### 导出链

同一编辑快照 → 完整时间线离线渲染 → 同一轨道/包络/TimePitch 语义 → 现有编码与安全保存。

- 导出总时长是工程最后片段末端经会话速度换算后的长度，不能只导出当前试听过的范围。
- 当前鸿蒙导出 WAV 48 kHz/24-bit；PC 原有格式/采样率/位深选择保留。
- 导出显示真实进度、取消、失败、完成和保存位置；取消文件选择不清空工程。
- 原文件不覆盖；临时输出完成校验后再交付目标文件。缓存按编辑修订号失效，导出不能命中过期结果。
- 退出只清理本编辑会话所有的临时文件、录音和句柄；不删源音乐、用户导出文件、模型或其他工具缓存。

## 15. 当前鸿蒙限制，不能误写成完整 DAW

当前六轨实现的边界为：6 轨、64 个源文件、工程最长 60 分钟、分割时最多 192 个片段、每片段 128 个音量点、40 个撤销检查点。PC 对应容量必须有显式校验；已有更高容量不得为了套手机数字而静默降级。

当前未实现：可扩展无限轨数、MIDI、多片段框选、自动交叉淡化、波纹删除、片段边缘拉伸、工程保存/重开、录音监听/伴奏叠录、插件链。PC 已有项目保留；没有的项目不纳入“照搬鸿蒙就已有”的交付声明。

## 16. 落地顺序

1. 确认实际 PC 编辑模型、播放/导出和右侧参数连接；记录当前行为作为保留基线。
2. 补轨道模型和每轨碰撞规则，先跑通三条不同起点素材的同步混音。
3. 接入六轨 UI、自动导入、点选、游标、缩放和滚动。
4. 接入同轨/跨轨拖动、吸附、分割、删除、撤销及音量点。
5. 接入录音和完整导出，保留 PC 原有输出设置。
6. 将右侧原有会话级参数接到混音总线，验证预览/导出一致。
7. 检查播放启动、松手定位、连续缩放和后台细节请求；有实际性能证据后再优化，不用假进度掩盖等待。
8. Windows 和真实 macOS 分别验收；报告区分代码测试、构建、界面、真实播放和听音。

## 17. 验收清单

- [ ] 一次选择 3 个/6 个真实文件，分别自动进入不同轨道；无需预先选轨。
- [ ] 有坏文件/无音轨视频/无空间时，其他正常文件仍加入，错误对应具体文件。
- [ ] 六轨不同起点同步播放，静音/取消静音和各轨音量真实生效。
- [ ] 播放不依赖整曲导出；波形分析不阻塞音频启动。
- [ ] 播放中拖游标：拖时顺滑且不反复加载，松手只在最终位置续播；暂停拖动保持暂停。
- [ ] 快速反复定位、缩放后定位、切换片段后定位，无旧结果覆盖和卡死。
- [ ] 放大后波形细节来自真实源区间；标尺和六轨完全对齐，末端不出现无意义空白。
- [ ] 同轨和跨轨拖动不回弹；吸附随缩放保持一致的视觉距离；碰撞/满轨明确失败。
- [ ] 跨轨后颜色、静音和整体音量属于目标轨；撤销恢复原轨和位置。
- [ ] 分割两侧音源和音量曲线连续；删除保留空白，不修改原文件。
- [ ] 双击加点、拖点、轨道音量与自动化相乘，在预览和导出中均生效。
- [ ] 录音到指定轨道和游标位置，权限/设备变化/停止/退出处理正确。
- [ ] PC 右侧保持原作用域和重置语义；升降调、BPM、共振峰保护预览与导出一致，没有重复变速。
- [ ] 完整导出的长度、声道、边界、静音区间、音量正确；无爆音、异常静音或明显接缝。
- [ ] 图标整齐、轨头高亮克制、波形无遮盖；Windows DPI/macOS 缩放与键鼠/触控板可操作。
- [ ] 退出未保存编辑有提示；取消导出或失败不会丢工程，用户源文件安全。
