## 性能证据

| 路径与输入 | 优化前 | 优化后 | 结论范围 |
|---|---:|---:|---|
| 12,000 条可见播放队列，重复及不存在 ID，5 次中位数 | 579.928 ms | 89.132 ms | QSet 去重保留队列次序；包含启动播放调用 |
| 同规模曲库，少于 5 首的回退队列，5 次中位数 | 655.509 ms | 71.246 ms | 保留原有小列表回退规则 |
| 8 MiB / 四层各 524,288 点波形缓存，5 次主线程调用中位数 | 92.988 ms | 0.615 ms | 大缓存加载/展开移到现有线程池；这是调用返回耗时，不能当作全部加载或渲染耗时 |
| 2,000 个真实 WAV 导入 | 3,524 ms | 2,835 ms | 同输入暖文件缓存单轮；最大 5ms 主线程心跳间隙 311→17 ms |
| 转换列表移除 2,000 条中选中的 1,000 条 | 481.419 ms | 14.541 ms | 消除平方级查找与逐条数组移动，保留剩余次序 |
| 400 个真实 FLAC 标签写入（未挂曲库） | 28,280 ms | 5,370 ms | 完成回写消除重复文件系统查询；最大心跳间隙 22,875→62 ms |
| 400 个真实 FLAC 标签写入并刷新曲库 | 18,375 ms | 9,165 ms | 400/400 文件与模型字段核验；一次批量通知，最大心跳间隙 356→17 ms |
| 8 个 30 秒 WAV→FLAC，2 并行，参数不变 | 118 ms | 119 ms | 编码速度基本相同；8 个输出参数/时长/总字节数一致，保留现有编码路径 |

频谱只在幅值实质改变后构造 QVariant 列表，保留现有通知阈值。波形保存及 QVariant 展开在现有工作线程执行，回主线程继续检查路径、曲目、代次及聚合模式；已加入大缓存完成排队后切换曲目的旧结果丢弃验证。视频保留既有按帧数/字节数限制的队列、后台解码和播放时钟驱动显示。

导入、库索引、转换与挂接真实曲库后的标签刷新，详见 `2026-09-05-full-import-convert-performance.md`。

上述导入/标签总耗时是单轮观测，期间独立依赖恢复与重建使未修改的编码用例也出现明显机器负载波动，不能将这些数值宣称为稳定吞吐倍率。可确认的改善是移除重复查询、二次扫描和逐文件 GUI 通知，并以真实输入测到了更短的主线程阻塞。

波形缓存优化已交由频彩任务负责人手工整合到主目录新的六层渐进实现；负责人回报 11/11 波形聚焦测试通过，六层最大缓存请求返回中位数 0.555 ms。上表四层数据是本任务隔离版本的实测，不能替代新算法完整显示耗时。最终合入补丁不再覆盖 `waveform_provider.cpp/.hpp` 和对应测试，以保留六层 API。

## 明确边界

- 本机是 Windows / Qt 6.7 / MSVC；macOS、Linux、Wayland 和其他音频硬件没有可用运行环境，不能据此保证这些平台已经完成原生适配验收。
- 文件生成和程序内播放测试不等同于人工实际听音。没有声称所有编码格式、网络盘、冷缓存或长时重负荷都获得相同收益。
- 导入线程数有界，但维持文件顺序的待交付结果仍可能因首个慢文件积累；没有把本次局部优化称作完整内存背压治理。
