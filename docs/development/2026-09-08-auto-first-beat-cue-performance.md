# 自动首拍 CUE 与轻量化修复

基线：main b9e11eb；本轮未提交、未打包。

## 行为

- 专业模式新曲沿用已有首拍分析。检测可靠或已有手动校准时，将首拍同时作为自动 CUE 和初始播放头位置。
- 手动 CUE 优先；自动 CUE 是当前曲派生状态，不覆盖磁盘上的人工标记。切歌后重新推导。
- 手动跳转/试听取消待执行的自动定位；删除 CUE 后本轮不自动重建。旧曲返回结果不能污染新曲。
- 低置信度结果不生成自动 CUE。此改动接通检测结果，不宣称对所有音乐能准确识别音乐学意义的小节第一拍。

## 性能调整

- 波形重复接收相同图层时复用原渲染快照，避免再次转换和构建频段摘要。
- 隐藏迷你窗口释放图层；重新显示读取共享会话的最新数据，不重复解码歌曲。
- 启动曲库加载使用移动语义，避免 main 在整个事件循环期间保留额外记录容器。
- 不降低波形分辨率、不强制修剪工作集、不改变播放核心和 QRhi 方向。

Ponytail 采用现有组件内最小修复，无新增依赖、功能删除或画质降级：

- PlaybackStateStore 仅成功保存后记住快照；全部序列化字段未变且文件仍存在时，跳过JSON构造和原子写盘。播放中的1秒检查点及退出保存不变。

- 迷你窗口最小化同隐藏一样释放图层，隐藏时忽略频谱刷新；恢复读取最新共享图层。
- 上述两项测试均先复现失败后通过；Release应用构建成功，4套相关CTest再次通过。

注意：此处收益是消除无变化时的写盘和不可见窗口工作，不能据此推导整个软件帧率提升比例。单实例邮箱轮询及播放中存储仍待单独测量。

审查发现的CUE问题（均有失败用例）：同曲显式重载未重置自动CUE抑制；网格校准后派生CUE仍停在旧位置；清除派生CUE插入空状态记录。
对应修复保持人工CUE独立；仅已存在的派生CUE随校准调整，删除后的CUE不因网格微调重新创建。
