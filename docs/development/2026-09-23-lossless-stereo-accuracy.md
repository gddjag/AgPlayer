# 无损鉴别：声道漏检修复与实测边界

日期：2026-09-23。算法 `lossless-1.18`，参数 `lossless-params-17`。

## 已确认的问题

原有 MDCT 检测在每个采样片段只分析最响的声道。已用实际 AAC 编码复现：

- 6 秒单声道 PCM，经 AAC 96 kbps 编码后解码为 WAV：`suspected_lossy_transcode`，kbd4 帧峰约 22.02 dB，z 约 21.76。
- 同一解码信号降低至 0.1 倍，放入右声道，左声道为更响的独立原始 PCM：旧版 `inconclusive`，漏掉较轻声道的压缩历史。
- 左声道原始 PCM 单独检测：`inconclusive`，作为不得指控有损来源的对照。

证据：`build/lossless-accuracy/before.json`。这是明确的声道覆盖盲点，不是修改判定阈值的理由。

## 实现

- `lossless_mdct.cpp/.hpp`：保留固定 4 个立体声片段。在已有检测没有形成压缩证据时，左右声道分别复核；相位、强度、显著性和片段数保持同一声道，不拼接两个声道的最强分数。
- 如果最响声道在全部有效片段中保持同一声道，直接复用已计算的结果，只追加另一声道的计算。新片段存储量受固定片段数约束，不缓存整首歌曲；不新增依赖或推理模型。
- `lossless_resampled_mdct.cpp/.hpp`：高采样率的独立降采样分析视图采用相同复核，在重采样尾部排空后执行，原始音频和位深统计不变。
- `lossless_analyzer.cpp`：将完整声道测量纳入原有判定，报告增加 `mdct_analysis_channel`，声道编号从 1 开始。新增证据说明不同声道可能具有不同来源，不能推定所有声道的完整历史。
- `lossless_types.hpp`：更新算法和参数版本，使旧缓存失效。判定阈值未降低，证据评分仍不是经校准的准确概率。

本轮针对立体声 MDCT 及其降采样分析视图。没有改写 CELT、DSD、位深或整套鉴别算法；多声道、所有编码器和全部处理链不在本轮覆盖范围内。

## 带编码历史的验证样本

基础源由固定种子 1907 / 8171 生成独立噪声与正弦组合，44.1 kHz、6 秒。编码使用已有 FFmpeg 6.1.1。样本、生成脚本、输入哈希和扫描结果保留在 `build/lossless-accuracy/`。

| 样本 | 当前结果 | 预期 |
|---|---|---|
| AAC 解码 WAV | 疑似有损转码 | 通过 |
| 较响原始 PCM + 较轻 AAC 右声道 | 疑似有损转码，证据声道 2 | 通过；原先漏检 |
| 上述文件左右互换 | 疑似有损转码，证据声道 1 | 通过 |
| 上述立体声文件升采样到 96 kHz | 疑似有损转码，44.1 kHz 分析视图 | 通过；不强行认证完整升频链 |
| 独立原始 PCM | 无法可靠判定 | 通过，未指控有损历史 |
| 两个未经压缩的 PCM 声道，响度不同 | 无法可靠判定 | 通过，未误报 |

结果及判定核对：`validation.json`、`validation-summary.json`、`input-hashes.json`。解码告警单独记录在 `validation-stderr.txt`。

## 用户提供的 MP3

只读分析 `F:/无损音乐/相识也是缘分(港风女声版） - 嘉欣.mp3`，时长约 255.26 秒。修改前的当前源码已经正确输出 `known_lossy_encoding`，当前编解码器 `mp3`，无分析错误；82 是工程证据分，不是来源准确率。

“原始来源未知”不是没有识别出 MP3。仅凭最终 MP3，不能唯一反推出此前来自 FLAC、WAV 或其他封装；FLAC/WAV 可以保存相同 PCM，再生成相同 MP3。用户提供的转换历史应与文件自身可测证据区分，不能硬编码成自动判定。

用户原文件未修改、未上传，测试派生文件仅写入工作区 build 目录。其封面/跳过样本时间戳解码告警未导致音频分析失败，保留在 `user-mp3-before.json` 的日志前缀中。
