工作区 `macos-sync-20260920`，基线 `eae61589`。用户反馈：播放期间持续不流畅、顶起不跟拍；设备为 2014 年 Intel i7 2.5 GHz / NVIDIA 750M。未取得当前 Mac 测试包标识或实机帧时间，不能将问题直接归因于硬件。

## Windows 对照

与 `pc-six-track-editor`（检查时 HEAD `29db0c06`）比较，反应堆 item、音频特征控制器、音频帧分析器、频谱/地形响应、snare 分析及地形顶点/片元着色器的核心路径一致；QML 沉浸面板无语义差异。Windows 工作区另有进行中的未提交修改，未写入该工作区。

Windows 本地 Qt 为 6.7.0 / D3D11；Mac 工作流使用 Qt 6.8.3。源码一致不能证明两个设备的 GPU 负载、运行时帧率或当前安装包一致。

## 已实施的局部修复

1. `TerrainShadowMap::configure` 使用与片元着色器 `referenceMode` 相同的条件，跳过标准主题不读取的地形阴影绘制。绑定的深度纹理仍初始化，自定义材质仍可恢复阴影。不改变网格密度、分辨率、材质、音频增益和主题颜色。
2. 定时刷新切换到逐帧刷新时，在停掉定时器前请求首帧。此前 Balanced -> High 在采样数/目标不变时可能停止绘制。回归测试移除窗口 resize，防止无关刷新掩盖缺陷。

## 节奏诊断与待确认方案

现有 `VisualAudioFrameAnalyzer` 每绘制一帧执行一次。FFT 和频谱特征平滑使用固定的每帧系数，顶起峰值检测同样按帧推进。低帧率会改变时间响应；仅同步相同源码不能消除这种差异。

一次性诊断入口 `build/import-regression-src/reactor_cadence_probe.cpp` 直接调用现有分析器与地形响应，用 48 kHz、70 Hz 指数衰减鼓点、120 BPM、36 拍，排除最初 4 拍，比较不同绘制频率。衰减参数 35 和 70 均得到：

| 模拟绘制帧率 | 匹配鼓点 | 平均检测延迟 |
| --- | --- | --- |
| 60 FPS | 32/32 | 33.3 ms |
| 30 FPS | 32/32 | 66.7 ms |
| 20 FPS | 32/32 | 100.0 ms |
| 15 FPS | 16/32 | 100.0 ms（仅已检测拍） |

日志 `build/reactor-cadence-results.txt`。这是受控合成 PCM 诊断，不是用户 Mac 的测量，也不能代表任意曲目准确率。

标准主题 High 分支还会覆盖自动降载的分辨率、网格和采样预算。本次未改此策略，避免未经实机验证降低画质。

已向用户提出：以 Windows 60 帧的分析节奏为基准，将真实音频分析与绘制频率解耦，保留主题、播放核心及现有依赖。因为这改变分析调度，等待用户确认后实施；当前未修改鼓点检测算法/调度，不能声称已解决 Mac 跟拍问题。
