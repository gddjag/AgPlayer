## 1. 目标与产品结论

保留并完整重构“频彩波形”。最终模式必须以真实的完整主波形、低频、中频、高频和播放焦点组成同轴透明叠层；颜色表达频率，不得退化为沿时间轴换色。

本次同时解决当前实现的以下差距：

- 当前分析器先完整解码一次统计帧数，再完整解码一次生成波形。
- 当前按声道分别滤波并累积，没有先执行立体声等功率下混或多声道安全下混。
- 当前分频为 250 Hz / 2 kHz 的二阶滤波，不是规范要求的 180 Hz / 2.8 kHz 四阶 Linkwitz-Riley。
- 当前只能在 Peak、平均绝对值或 RMS 中选择一种，没有 `0.70 × Peak + 0.30 × RMS`。
- 当前使用最大值归一化，没有 99.5% 分位参考、-72 dBFS 门限、0.62 显示压缩和 7/5/3 点分层平滑。
- 当前所有普通波形分析都会顺带生成三频层，不符合延迟按需生成边界。
- 当前工作树中的未提交视觉改动未采用“曜釉”固定色值，只支持低/中/高三色和一个全局透明度；主波形底层不能自定义。

## 2. 范围

### 2.1 必须交付

- 单次 PCM 解码生成所请求的主波形和三频包络。
- 主波形底层、低频、中频、高频四层分别支持深浅主题颜色和透明度设置。
- “曜釉”深浅两套默认色值和透明度严格匹配输入规范。
- 独立、版本化、可校验的三频缓存；颜色和透明度变化不触发重新分析。
- 三频按需后台生成，主波形立即可见，完成后 120–180 ms 淡入。
- 预乘 Alpha SourceOver、填充与描边、同色相播放进度和轻量播放焦点。
- 点击定位、Scrub、缩放、Cue、选区、主题切换、窗口缩放和高 DPI 保持兼容。
- 分析失败、取消、缓存损坏、软件渲染和低性能状态均能安全降级。
- 自动化测试、深浅主题截图、性能与缓存增量记录写入 `docs/development/`。

### 2.2 明确不做

- 不引入大型 DSP、视觉框架、模型或运行时。
- 不在播放线程或播放输出链中加入分频处理。
- 不做逐帧 FFT、全屏模糊、长期 Bloom、闪烁或呼吸动画。
- 不默认对歌曲列表缩略波形启用完整频彩分析。
- 不在普通设置中开放分频点、FFT 大小、滤波阶数、频段增益或缓存精度。
- 本任务不制作或发布安装包；安装包体积只做构建产物对比，真实安装发布另行验收。

## 3. 总体架构

```text
WaveformSession / 播放器界面
              │
              ▼
       WaveformProvider
       ├─ 现有主波形缓存（AGWF）
       └─ FCW1 三频独立缓存
              │
              ▼
       单次 FFmpeg PCM 解码
              │
      ┌───────┴────────┐
      ▼                ▼
完整主波形       FrequencyColorEnvelopeProcessor
                  ├─ 等功率/布局安全下混
                  ├─ LR4 分频
                  ├─ Peak + RMS
                  ├─ 共享归一化
                  └─ 分层平滑
      └───────┬────────┘
              ▼
         WaveformItem
         ├─ 主波形底层
         ├─ 低频层
         ├─ 中频层
         ├─ 高频层
         └─ 播放焦点
```

架构原则：

- 保留 `WaveformItem` 现有时间映射和交互接口，避免出现第二套行为不一致的波形控件。
- 三频 DSP 放在独立内部模块，仍由现有 FFmpeg 解码管线供给 PCM。
- 主波形和三频缓存分离；三频算法升级不得连带清空普通主波形缓存。
- `WaveformProvider` 负责主波形与三频结果的组合、任务优先级、取消和发布。
- 未选择频彩模式时不得启动三频滤波、读取三频缓存或更新三频图层。
- 播放焦点统一由 `WaveformItem` 渲染，删除主播放器、迷你播放器、集成播放器和沉浸式视图中的重复焦点实现。
- 不改变其他三种波形模式和播放器核心播放逻辑。

## 4. 单次解码与包络算法

### 4.1 请求模式

分析入口区分 `MixOnly` 与 `MixAndFrequencyBands`：

- 普通模式使用 `MixOnly`，不构造三频滤波器。
- 频彩模式且缓存未命中时使用 `MixAndFrequencyBands`。
- 主波形缓存已存在而 FCW 缓存缺失时，界面先发布主波形；后台分析只发布新的三频结果，仍只打开一个解码器。

### 4.2 下混

- 单声道直接使用该样本。
- 立体声使用 `mono = (left + right) × 0.70710678`。
- 多声道根据 FFmpeg 声道布局构造安全下混矩阵，不直接取第一个声道；LFE 和环绕声道使用明确、可测试的衰减权重。
- 非有限 PCM 立即使分析失败并清空未发布结果，不能把 NaN/Inf 写入缓存。

### 4.3 分频

- 低频：20–180 Hz。
- 中频：180 Hz–2.8 kHz。
- 高频：2.8 kHz–`min(20 kHz, 0.45 × sampleRate)`。
- 180 Hz 和 2.8 kHz crossover 使用两级二阶 Butterworth 级联形成四阶 Linkwitz-Riley。
- 低频入口和高频出口应用稳定的边界滤波；低采样率导致上限不高于 2.8 kHz 时，高频层为空并触发主波形安全回退策略，不产生不稳定系数。

### 4.4 时间桶与内存上限

解码时不保存整首 PCM。`Decoder` 在打开流时把 FFmpeg 的高精度 stream duration 按输出采样率换算为 `timelineFrames`，分析器固定创建 2000 个时间桶，并用以下映射在单遍读取中直接累计 Peak、平方和与样本数：

```text
bucket = min(1999, absoluteTimestampFrame × 2000 / timelineFrames)
```

空时间桶保持零；跨块滤波器状态连续；PTS 倒退、重叠或非有限样本使三频分析失败。容器没有可靠时间轴时，频彩分析返回“不支持”并保留已有主波形，不以第二次完整解码伪装成单遍实现。`timelineFrames` 与实际 `decodedFrames` 分开记录，处理 VBR、priming、padding 和损坏流时不混淆两种语义。

因此流式统计内存严格与 2000 个目标桶相关，而不是与歌曲时长线性增长；单遍性通过测试用 decoder open/read 计数器验证。

### 4.5 包络后处理

每个最终桶和每个图层计算：

```text
rms = sqrt(sumSquares / sampleCount)
envelope = 0.70 × peak + 0.30 × rms
```

随后：

1. 低频 0 dB、中频 -1 dB、高频 +3 dB 感知补偿。
2. 低、中、高分别执行 7、5、3 点对称平滑；主波形保留现有轮廓行为。
3. 用整首歌曲各桶四层最大能量的 99.5% 分位值作为一个共享参考，不对三个频段分别归一化。
4. 小于 -72 dBFS 的值归零，只保留渲染端中心基线。
5. `display = pow(clamp(value / reference, 0, 1), 0.62)`。
6. 最终值限制到 0.98。

## 5. 缓存与调度

### 5.1 FCW1 格式

主波形继续使用现有 AGWF 缓存。三频缓存使用独立 FCW1 文件，包含：

- 4 字节 magic 与格式版本。
- 分析算法版本和参数哈希。
- 源文件 canonical path 指纹、大小和 mtime。
- sample rate、point count、180/2800 Hz crossover 和有效高频上限。
- `low/mid/high` 三个等长 `uint8_t` 数组。
- payload 长度和 CRC32。

写入沿用临时文件、flush、原子替换；读取先验证头部、文件长度、数组数量和 CRC。任一校验失败时忽略旧文件并后台重建，不影响主波形或播放。

2000 点时三层 payload 为 6000 字节，连同头部和校验应控制在约 8 KiB/歌曲。现有缓存清理器同时管理 AGWF 与 FCW 文件。

### 5.2 生成时机

- 启动时不扫描曲库、不创建三频工作线程。
- 选择频彩模式后才读取或生成当前歌曲的 FCW。
- 当前歌曲任务高于任何可选预取；三频预取默认关闭。
- 同时最多一个三频分析任务，使用低优先级线程和可协作取消标志。
- 切歌、离开频彩模式、窗口不可见或任务身份过期时取消；取消结果不得写缓存或发布到新歌曲。
- 播放出现 underrun、系统进入节能状态或应用请求暂停后台工作时，分析在解码块边界等待；恢复后继续，不忙轮询。
- 主波形先发布；FCW 完成后再发布同一 track ID 与 generation 的完整三频层，并以 120–180 ms 淡入。

## 6. SceneGraph 渲染

### 6.1 图层与节点

固定从后向前：

1. 中心基线。
2. 主波形底层。
3. 低频层。
4. 中频层。
5. 高频层。
6. 同色相播放进度处理。
7. 播放焦点。
8. 现有 Cue、选区、标记和交互覆盖层。

四个波形层各自最多一个 `QSGGeometryNode`。每层使用一个索引三角形网格：填充面、上描边 ribbon 和下描边 ribbon 共用一次 draw，顶点属性区分填充与描边 Alpha；不使用逐点 QML Rectangle。自定义轻量材质通过 item-local x 计算连续播放进度，输出预乘 RGBA，显式启用 `QSGMaterial::Blending`，采用 Qt RHI 的 premultiplied SourceOver。

软件 SceneGraph 后端不运行自定义 shader：切换到有界点数的 `QSGVertexColorMaterial` 线条回退路径，只显示主轮廓和三频描边，保证能用但不假称完整 GPU 效果。

### 6.2 更新边界

- PCM/缓存 revision、尺寸、缩放范围、可视区、密度或 DPR 改变时重建几何。
- 颜色、透明度、主题、三频淡入和播放进度只更新材质参数。
- 播放焦点使用独立轻量节点和横向 transform；播放期间不重建四层顶点。
- 已播放区域保持原色；未播放区域 Alpha 乘 0.72，饱和度最多降低 8%，焦点附近做窄幅平滑过渡。

### 6.3 曜釉固定令牌

| 图层 | 深色颜色 | 深色填充 | 深色描边 | 浅色颜色 | 浅色填充 | 浅色描边 |
|---|---:|---:|---:|---:|---:|---:|
| 主波形 | `#7A8490` | 18% | 38% | `#59636D` | 14% | 36% |
| 低频 | `#269A8E` | 44% | 82% | `#146B64` | 36% | 78% |
| 中频 | `#C66B55` | 38% | 80% | `#9D4938` | 32% | 76% |
| 高频 | `#B5A4C6` | 46% | 84% | `#6E5A7D` | 40% | 80% |

播放焦点深色为 `#F2E7D4`，浅色为 `#26313A`；1 dp 核心线、两层低透明度轻量柔光和 5–7 dp 交叉点，不随音乐强度闪烁。

### 6.4 自适应质量

- 高度 ≥120 dp：完整填充、描边、主层和焦点柔光。
- 64–119 dp：全部图层，缩小柔光。
- 32–63 dp：减弱填充，保留三频描边和主轮廓。
- 小于 32 dp：简化主波形和三频综合色，不作为主播放器默认尺寸。
- 软件渲染或持续帧时间超标时按 `Full → Balanced → Low` 降级；恢复采用更长观察窗口和滞后阈值，避免反复切换。
- FCW 必须三层完整且校验通过才淡入；缺失、损坏或低采样率不可用时只显示主波形。

## 7. 设置、主题和迁移

### 7.1 设置界面

频彩模式显示：

```text
配色预设：曜釉 / 自定义
编辑预览：深色 / 浅色

主波形底层   [颜色] [透明度]
低频         [颜色] [透明度]
中频         [颜色] [透明度]
高频         [颜色] [透明度]

播放焦点     [开关]
恢复曜釉默认
```

- 四层颜色和填充透明度分别编辑，透明度 0–100%，步长 1%。
- 透明度为 0 时整层隐藏；描边相对于该主题默认填充透明度按比例缩放。
- 任一编辑将预设切换为“自定义”，原生缩略图立即更新但不触发分析。
- “编辑预览”只切换预览与编辑目标，不强制切换整个应用主题。
- 用户编辑一个主题颜色后，通过 OKLCH 自动生成另一主题版本；用户可切换到另一主题继续手动微调。
- 自动适配保留 Hue、限制过高 Chroma，并优先调整 Lightness，使描边与主题背景的目标对比度不低于 3:1。
- 播放焦点只提供开关，不开放颜色或透明度。

### 7.2 设置职责

新增轻量 `FrequencyColorWaveformSettings`，由 `SettingsController` 持有并复用现有编辑确认、取消和 `QSettings` 生命周期。它管理预设、深浅主题四层颜色/透明度、自动/手调标记、焦点开关和 schema version；不创建线程或服务。

音频缓存不保存任何颜色、透明度或主题字段。

### 7.3 一次性迁移

- 以显式 settings schema version 控制，只执行一次。
- 已知历史内置三色组合迁移为曜釉默认值。
- 未知或部分修改的旧低/中/高颜色按用户自定义值保留，并自动生成另一主题版本。
- 旧 `waveformFrequencyStrength` 按旧角色透明度比例转换为三层新透明度；主波形使用曜釉默认值。
- 旧键暂时保留但不再作为新设置的真源，支持用户回退旧版本。
- 迁移完成后不得继续通过颜色元组猜测用户意图。

## 8. 错误处理与恢复

- 解码、滤波、非有限样本、缓存读写或取消任一失败：记录可诊断错误，清空临时三频数据，保留主波形和播放。
- 临时文件只在完整写入、flush 和 CRC 成功后原子替换目标文件。
- provider 以 track ID、source path、generation 和 mode request 四项核对结果，阻止快速切歌后的旧结果发布。
- UI 只在三个频段长度一致、point count 合法且来源身份匹配时淡入。
- 设置中的非法颜色回退到对应曜釉令牌；透明度执行有限数检查、0–1 钳制和 0.01 量化。
- SceneGraph 节点分配失败、软件渲染不支持完整材质或数据量异常时使用 Low 模式或只显示主波形，不崩溃。

## 9. 性能预算

以下是交付门槛，不是当前已验证结果：

- 非频彩模式启动、播放 CPU 和主波形加载中位数回归均不超过 3%。
- 频彩首次分析不得慢于当前双遍分析基线。
- FCW 缓存约 8 KiB/歌曲；不启动全库预分析。
- 同时最多一个三频分析任务；切歌和退出模式可取消。
- 频彩模式额外常驻内存控制在数 MiB 内，具体值由实施后的基准记录。
- 4K 主播放器在可用 GPU 上保持目标刷新率；快速拖动和缩放不得阻塞 UI 或引发音频 underrun。
- Release 可执行文件与所需资源净增不超过 1 MiB；不引入新 DLL。
- 任一门槛不满足时不得宣称完整完成，应修复或启用有证据的降级路径。

## 10. 测试与验收

### 10.1 Core 单元测试

- 44.1/48/88.2/96/192 kHz 的滤波系数稳定性。
- 100 Hz、1 kHz、8 kHz 纯音分别由低、中、高层主导。
- crossover 邻域连续性与 LR4 幅相组合。
- 立体声同相、反相和单边信号；多声道布局下混。
- Peak+RMS 脉冲、正弦、粉红噪声、静音、渐入渐出、削波和 NaN/Inf。
- 99.5% 分位不被单个异常尖峰支配，三层不被分别归一化。
- 7/5/3 点平滑保留低频厚度和高频瞬态。
- 单次解码调用计数与超长音频中间内存上限。

### 10.2 缓存与 provider

- FCW1 round-trip、CRC 损坏、截断、错误版本、源文件变化和算法版本升级。
- cache miss 后原子写入；取消/失败不留下可加载的半文件。
- 主波形先发布、三频后发布；cache hit 不启动分析。
- 快速切歌、重复请求、模式切换、窗口不可见和 provider 析构时不发布陈旧结果。
- 普通模式不读取或生成 FCW。

### 10.3 Qt/SceneGraph

- 四层节点顺序、填充/描边顶点、预乘 RGBA 和材质 blending 标志。
- 曜釉深浅颜色与填充/描边 alpha 精确断言。
- 四层自定义颜色和透明度互不影响。
- 只更新播放进度材质参数和焦点 transform，不重建波形几何。
- DPI、宽高变化、缩放、软件渲染和 Full/Balanced/Low 降级。

### 10.4 QML 与交互

- 设置页四层颜色/透明度、深浅预览、焦点开关、恢复默认和一次性迁移。
- 主、迷你、集成、沉浸式视图使用同一频彩设置与焦点实现。
- 点击定位、Scrub、缩放、hover、Cue、选区和时间显示回归。
- 三频分析中、失败和损坏缓存时保持主波形可交互。

### 10.5 视觉与性能证据

- 深色、浅色、跟随系统截图。
- 100/125/150/200% DPI；720p/1080p/2K/4K；窄窗、宽窗和全屏。
- 灰阶、常见色觉缺陷模拟和低亮度显示器检查。
- 首次分析、缓存命中、连续切歌、长音频、缩放拖动的 CPU、内存、帧时间和缓存大小。
- Release 构建产物体积前后对比；不把 Debug、单个 focused test 或一张截图描述成完整验收。

## 11. 实施顺序

1. 用失败测试锁定下混、LR4、Peak+RMS、共享归一化、平滑和单次解码。
2. 实现 FCW1 缓存、算法版本与 provider 延迟调度。
